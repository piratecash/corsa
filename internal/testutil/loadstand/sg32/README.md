# SG32 preparation harness

This is a diagnostic preparation tool for the [approved profile](../../../../docs/operations/d1-service-group-memory-profile-proposal.md). Production defaults remain unchanged.

`sg32_host.py` controls one separately admitted attempt. `sg32_service.py` contains the preparer, keeper and owned-child sampler. `sg32_common.py` validates retained evidence; `test_sg32.py` exercises actual functions with local fake boundaries. Container inputs reuse `../clockprobe/probe.py` as `clockprobe.py`; do not substitute an older reader.

Import performs no resource work. An incomplete, unapproved or unqualified admission refuses before Docker access. A final execution packet must pin these sources, the canonical heavy wrapper, the exact image, reviewed qualifications and the actual CLI/driver bytes. Preparation approval does not permit compilation or execution. The qualified execution packet must enter through `bootstrap.py` using isolated Python (-I -S -B). It validates actual fixed Host/common paths and captured bytes before controlled loading, binds them to the runtime inputs and rejects pre-existing subject modules. `bootstrap_sha256` is a required admission field.

The service budget is 1 CPU / 512000000 bytes / 64 tasks without swap, including corsad, keeper and sampler. Useful work must complete: 32→16→32→0 TLSv2 sessions, 48 identities and 224 source-bound sequences. A small peak without this work is not success.

The selected kernel peak window ends at the keeper read after daemon and sampler reap. Keeper exit-tail, physical shared pages and isolated role attribution remain UNKNOWN. Optional RSS/HWM/PSS are not collected by this version. Cgroup, clock, process, network and workload evidence are mandatory; missing evidence refuses qualification.

Do not run the host controller by hand. Use the separately reviewed immutable execution packet under the canonical heavy wrapper. Unknown physical closure retains the live controller and lock for operator recovery. No automatic retry, backend switch, growth of limits or lock removal is implemented.

The activation helper encodes its payload before checking a fresh remaining budget of at least 125 seconds, after driver create/inspect/start. Bootstrap entry time is propagated internally so preflight and loading remain inside the same 180-second work and 30-second cleanup limits. Expired entry/commands refuse before resource creation. These two engineering gates have pure-test evidence; actual execution still requires qualified ELF bytes and separate admission.
