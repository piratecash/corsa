# Неактивный intake FindNode и исторический owned cut

Этот срез связывает исходное наблюдение Node с непрозрачным `findnode.OwnedCut`. Новый приватный root не имеет production callers; домен остаётся Constructing. Приём запросов, обработчик, wire/config, G2 и активация отдельно. Явный профиль конструктора является входом проекта, а не профилем развёртывания.

Runtime-конструктор принимает исходный runtime Consumer, fixture-конструктор — настоящий tagged fixture Consumer. До выделения состояния проверяются timing, round/slack, tokens, M и арифметика размеров. Создаётся ровно один owner, coordinator, source owner и capacity domain. Без hint сохраняется bootstrap512 и начало эпох в нуле. Owner и sink образуют исходную пару; разные приватные поля не позволяют преобразовать capabilities друг в друга. Копия handle сохраняет владельца; Seal не создаёт его заново.

Новый путь Node создаёт исходный домен и роли наблюдения, затем пару до FIRST Service literal и callbacks общего builder. Старые observation-only корни сохраняют нулевую пару; односторонняя пара отклоняется claim. Метод cut ровно один раз вызывает неизменённое наблюдение. После подлинного q, полученного после последнего ожидания Node, остаются только полное позиционное преобразование и чистый Seal. Новых sample, locks, callbacks, отбора цели или oldest-four нет. Новый root и cut не имеют production callers.

Seal сначала проверяет исходные stamp/q/Consumer и исключительную degree/history границу. Диагностические счётчики проверяются по отдельности до сложения: 0..64, outgoing+incoming=window. Все исходные Session и классы копируются позиционно через неизменённую проверку S3B1. Нулевые, закрытые, недоказанные, дублирующие ConnID или открытые после q записи отклоняются. Пустой подготовленный набор отличается от нулевого cut; буфер DTO вызывающего не сохраняется. В Session нет bridge-domain: сам DTO не доказывает происхождение из Node и полноту. Эта связь ограничена фактическим закрытым callsite Node.

Cut хранит исходные stamp/q, owner/Consumer, один защитно скопированный вектор Session, отдельный вектор классов, degree и одну исключительную границу. Она равна проверенному минимуму исходной degree/history границы, перехода opened+600 секунд **каждой** молодой Ordinary Session и следующей 600-секундной capacity-эпохи от нулевого начала домена. При q=600 секунд следующая граница — 1200. Для Contact/Selected не вводится ordinary-переход, для IncomingPinned не выдумывается защита. Переполнение любой необходимой конечной границы даёт отказ. Равенство final time границе недопустимо; round/slack и срок forwarding эти исходные ограничения не заменяют.

Seal не берёт lease и время, не изменяет coordinator/capacity/source debt, не создаёт pending/alias, worker или I/O. Это исторический результат: writer или End может сразу сделать stamp устаревшим. Seal не переписывает stamp/q и не обещает текущую generation, открытый lifecycle либо commit.

Именованные функциональные SOURCE-тесты используют настоящие TLS Session для proof/copy/classes; ConnID/group/opened явно обозначены логическими входами fixture. Node fixtures создают исходные FixtureDomain/roles/пару до builder; затем только исходный publisher явно seals домен. Listener/P1 и реальный CM fallback receipt сохраняют подлинные cleanup joins. Непрозрачный Node cut не получает getter или чёрный ящик для обнаружения пропусков: дополняют друг друга точное SOURCE-замыкание преобразования и приватные findnode-тесты. Десять причинных recipes подготовлены для последующего выполнения и имеют статус NOTRUN. Здесь не заявляются compilation, guards, functional/race PASS или physical RED.

Отдельно остаются final combined TryReadClock(stamp), sampleAndCheckOriginals по **всем** исходным Session после actual final sample, f>=q, строгая граница, source/calendar/round/capacity predicates, ограниченный scratch, source CAS и безотказный commit без последующих ожиданий Node. Полнота writer closure, число удерживаемых cut S и стоимость S*M, ресурсы, G2 и активация не закрыты. Преобразование persisted loaded hint в bootstrap этого owner ещё не реализовано; producer и loaded evidence не устанавливались. Утверждённое наблюдение d_win=600 секунд и прежние правила установки/flush statistic не меняются.
