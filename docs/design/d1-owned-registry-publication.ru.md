# Кандидат публикации реестра D1

Реализация использует исходный неизменяемый publisher, установленный до первого литерала Service. Обычные конструкторы оставляют attachment пустым и не выделяют registry publication. Частный root остаётся Constructing: Ready, полный reader/cut, публичные настройки и активация не добавлены.

Четырнадцать функций содержат пятнадцать локальных ветвей nonclock W. Все прежние ожидания peerMu, deliveryMu, common и readiness происходят до W. Внутри выполняются только перечисленные изменения памяти; Complete предшествует новым блокировкам, callback, логированию, часам, Close и IO. Для обычной nil-ветви Complete вызывается только после проверки указателя: leaf API отвергает nil. Go map может выделять память, а runtime — остановить goroutine; временная и ресурсная гарантия этим не устанавливается.

Вставка публикует обе исходные записи реестра вместе. Привязка транспорта публикует проверенную взаимную связь entry/common/ConnID, затем независимо проверяет N-in вне W. Квитанция CM выделяется заранее под прежним peerMu. Только настоящий callback принятого поколения записывает selectedGeneration и успешно подготовленную квитанцию в одной W. Неуспешная подготовка сохраняет старую квитанцию. Последующая публикация F1 по-прежнему проверяет полный исходный tuple, authentication, роль, точный entry/текущий Session и принятое поколение.

unregister под peerMu находит исходный secondary key, завершает исходный common End, закрывает его receive и освобождает budget. Лишь затем отдельная registry W удаляет обе записи. End самостоятельно берёт common → degree → clock → W; внешняя W вокруг End недопустима. Отмена, poison часов и отказ наблюдения не отменяют очистку. Stamp между End и удалением может видеть terminal-состояние; удаление делает этот stamp устаревшим. Полного capture здесь нет.

Точные проверки указателя Session в CM сохранены: поздняя очистка A не удаляет текущий B. Прежняя address-only очистка legacy не получает этого обещания. Замена указателя map не вводит автоматический End заменённого Session. Политика исчерпания/повторного использования ConnID здесь не определяется.

Для End, F1 и очистки при отмене/poison тесты получают настоящие TLS/common/P1. Вставка реестра изолируется обычным core без proof, чтобы другая публикация не скрыла пропущенную W. Для удаления второй stamp берётся после завершившегося End. A/B fixture сохраняет настоящие proof и degree origins, задавая только LocalAddr исходного server до TLS ради одного управляемого ключа адреса; принятую квитанцию CM или опубликованную F1 для B не подделывает. Настоящий callback CM/F1 проверяет прежний S1 тест. Только в тесте с удерживаемой W dispatch выполняется отдельной зарегистрированной goroutine с обязательным join; production callback остаётся синхронным.

SOURCE guard фиксирует 15 ролей вызова helper, 13 прямых точек записи registry/session maps и 27 явных compact-raw хешей тел функций. Это конечный синтаксический контракт, не полный typed alias analysis. Опасные nested-W, ранний/concurrent Complete и callback внутри W проверяются как SOURCE там, где нет законного детерминированного функционального шва. Заведомый deadlock-мутант не исполняется. FORMAT/TYPE/обычные/race проверки ещё требуются.

H7 сохраняет 100 физических строк/92 ключа. Добавлен ровно один leaf-importer conn_registry.go: всего девять. Pin/trust inventories получают одну точную строку beginRegistryPublication. RAW36 сохраняет побайтовый SHA256 и прежние 36 путей; изменённый литерал find_node_connection.go и точная строка common.Lock перепривязаны в SOURCE. После реального FORMAT все 36 хешей и тот же callsite нужно прочитать и подтвердить независимо.

Полное замыкание writers/readers/cut, остальные core/auth/tracked metadata, admission, Ready/Seal, G2, ресурсная приёмка, активация и выпуск остаются открытыми. Завершение D1 этим срезом не заявляется.
