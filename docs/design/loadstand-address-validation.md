# Load-stand primary address validation

## English

The private node test-package function `validateLoadStandPrimaryIPv4` checks an explicit address table against a plan-v3 value. It is a static precursor of a topology launcher. It performs no network or filesystem I/O, starts nothing, and is not connected to the executor, Linux owner, RPC or a production entry point. Its result is ordinary copied diagnostic data, not a start receipt, ownership proof or admission capability.

Each planned node has one `loadStandPlannedAddress` row with its node ID, a literal address and an explicit ordered bootstrap list. The validator checks the plan's digest, a single version-3 parameter, canonical full/edge IDs in the existing plan order, known roles and FULL-only hub roles. It does not regenerate the random plan from its seed or change its graph. Unknown, duplicate, missing or additional rows are refused without returning a partial result.

Addresses must be canonical IPv4 `host:port` literals in **240.0.0.0/4**, with decimal ports 1–65535. DNS, IPv6, mapped addresses, zones, whitespace, bracket/port aliases and addresses outside the primary range are refused. This function does not allocate addresses or select a fallback range.

Classification uses the actual functions compiled from this source tree: `canonicalIPFromHost`, `classifyHost`, `isNonRoutableIP`, `subnetGroupKey` and `sourceGroup`. Each output row records the canonical IP, actual network/routability verdict, /24 subnet and /16 source group. The current verdict must be IPv4, routable according to the node predicate, and the expected canonical /24 and /16 containing that IP. This is a static verdict of this source label; it is not proof that the kernel routes or isolates that address. A comparison label must use its own functions, not a copied HEAD classifier. Missing old-label functionality remains an explicit unavailable dependency.

Every IP, endpoint and actual source group must be distinct. FULL nodes must additionally have distinct actual /24 subnets. With distinct /16 groups, **240/4 has a finite capacity of 4096 total nodes, counting FULL and SDK**. The validator explicitly refuses larger node or candidate tables before copying/classifying them. This profile does not support all 10000 nodes of act D and does not switch to shared groups, H-loop or a different address range. A passing 4096-row static fixture is not a claim of runtime support for 4096 processes. The /24 check is retained separately, although /16 uniqueness currently implies it.

An SDK address denotes a planned source/protocol address, **not a listener**. Role comes from the plan. SDK remains a client without a listener and cannot be a bootstrap target. Every node, including every hub, must have a nonempty bootstrap list exactly matching its ordered `DialTargets` projected onto the explicit FULL addresses. Self, duplicate, unknown, SDK or reordered targets are refused. The validator never fills an empty list, adds links, sorts configuration, self-dials or inserts a public seed. The existing one-hub plan has an empty hub bootstrap and is therefore refused by this physical-address check; its generator is unchanged.

Inputs must be race-free while the pure call runs. Candidate rows/bootstrap lists are cloned; result accessors return fresh row/bootstrap copies. Mutating the caller's inputs or a returned snapshot after validation does not change the retained result. The output also carries the exact plan digest. There is no clock, lock, worker, queue, retained history, private key or teardown authority.

Incremental address work is O(N+B+T) for N nodes, B bootstrap entries and T input-text bytes parsed or hashed (including malformed inputs). Valid literal widths are bounded, but arbitrary invalid input text is not assumed constant-sized. Checking the existing canonical plan digest and obtaining `Nodes()` also processes/copies the plan's serialized content and node slices, including contacts. Those pre-existing O(P) costs are not hidden: the total bound is O(P+N+B+T), with temporary maps/slices and the canonical digest encoding. No measured-node resource cost or new global runtime quota is claimed.

The companion contract tests cover generated small plans, exact grouping tuples, identity/digest/version failures, canonical/range failures, SDK source diversity, bootstrap/graph/order failures, copy isolation and 4096/4097/10000 capacity boundaries. Large boundary fixtures assemble only a pure topology/digest value, avoiding unrelated quadratic contact-selection fixture allocations; they launch no nodes. A small AST check pins direct calls to the actual same-tree classifiers. This is a **source-placement check**: replacing a classifier with a constant can be behaviorally equivalent over today's admissible range. Similarly, removing the separate /24 check need not fail a behavioral test while /16 uniqueness holds. Neither is reported as a qualified semantic runtime mutant without a counterexample.

Still separate are a topology/address allocator, kernel namespace/isolation/source-IP evidence, real node-generated identities, readiness, independent `MemberStart`, final accounting, restart, calibration/resource acceptance, native CGO qualification, cross-label reproducibility, heavy scenarios and G2 activation. The existing loopback-only child configuration, SDK functional overrides, Observe correlation boundary and `FinalUnavailable` behavior are unchanged.

## Русский

Приватная функция тестового пакета node `validateLoadStandPrimaryIPv4` сверяет явную таблицу адресов со значением плана v3. Это статическая предпосылка будущего launcher с топологией. Функция не выполняет сетевой или файловый I/O, ничего не запускает и не подключена к executor, Linux owner, RPC или production entry point. Её результат — обычные копии диагностических данных, а не квитанция запуска, доказательство владения или допуск.

Каждому узлу соответствует одна строка `loadStandPlannedAddress`: ID, буквальный адрес и явный упорядоченный bootstrap. Проверяются digest плана, единственный параметр версии 3, канонические full/edge ID в существующем порядке плана, известные роли и допустимость hub только для FULL. Случайный план из seed повторно не генерируется, его граф не меняется. Неизвестные, повторные, отсутствующие и дополнительные строки отвергаются без частичного результата.

Разрешены только канонические IPv4 `host:port` из **240.0.0.0/4** с десятичными портами 1–65535. DNS, IPv6, mapped-адреса, зоны, пробелы, алиасы со скобками/портами и адреса вне основного диапазона отвергаются. Функция не распределяет адреса и не выбирает запасной диапазон.

Классификация использует реальные функции, скомпилированные из этого дерева: `canonicalIPFromHost`, `classifyHost`, `isNonRoutableIP`, `subnetGroupKey` и `sourceGroup`. Строка результата сохраняет канонический IP, фактические network/routability, подсеть /24 и группу источника /16. Текущий результат должен означать IPv4, маршрутизируемый по предикату узла, и канонические содержащие IP группы /24 и /16. Это статический результат данной метки исходников, а не доказательство маршрутизации или изоляции ядром. Для сравниваемой метки нужны её собственные функции; классификатор из HEAD не подставляется. Отсутствующая функциональность старой метки остаётся явно недоступной зависимостью.

Каждый IP, endpoint и фактическая группа источника должны быть различны. Для FULL дополнительно проверяются различные фактические /24. При различных /16 **240/4 вмещает максимум 4096 узлов суммарно, включая FULL и SDK**. Большие таблицы узлов или кандидатов явно отвергаются до копирования/классификации. Этот профиль не покрывает все 10000 узлов акта D и не переключается на общие группы, H-loop или иной диапазон. Успех статической фикстуры из 4096 строк не означает возможность запуска 4096 процессов. Проверка /24 сохранена отдельно, хотя уникальность /16 сейчас её подразумевает.

Адрес SDK обозначает планируемый source/protocol address, **не listener**. Роль берётся из плана. SDK остаётся клиентом без listener и не может быть bootstrap-целью. Каждый узел, включая hub, обязан иметь непустой bootstrap, точно равный упорядоченной проекции `DialTargets` на явные адреса FULL. Self, повторы, неизвестные цели, SDK и иной порядок отвергаются. Функция не заполняет пустые списки, не добавляет связи, не сортирует конфигурацию, не выполняет self-dial и не вставляет публичный seed. Существующий план с одним hub оставляет его bootstrap пустым и потому отвергается этой проверкой физических адресов; генератор не меняется.

Во время чистого вызова входы должны быть свободны от конкурентных изменений. Строки кандидатов и bootstrap копируются; accessors результата возвращают новые копии строк/bootstrap. Последующее изменение входов или возвращённого снимка не меняет сохранённый результат. Результат также содержит точный digest плана. Здесь нет часов, блокировок, worker, очереди, истории, приватных ключей или права завершать процессы.

Дополнительная работа с адресами — O(N+B+T) для N узлов, B bootstrap-записей и T байтов входного текста, разбираемых или хешируемых (включая ошибочные входы). Ширина допустимого literal ограничена, но произвольный ошибочный текст не считается константным. Проверка существующего канонического digest и `Nodes()` дополнительно обрабатывает/копирует содержимое плана и его срезы, включая contacts. Эти существующие расходы O(P) не скрываются: итоговая граница O(P+N+B+T), с временными map/slice и канонической строкой digest. Стоимость измеряемого узла и новая глобальная runtime-квота не заявляются.

Контрактные тесты охватывают маленькие сгенерированные планы, точные tuples группировки, ошибки identity/digest/version, каноничность/диапазон, различные SDK source groups, bootstrap/граф/порядок, изоляцию копий и границы 4096/4097/10000. Большие граничные фикстуры строят только чистое значение topology/digest, исключая несвязанные квадратичные расходы выбора contacts; узлы не запускаются. Небольшая AST-проверка закрепляет прямые вызовы реальных same-tree классификаторов. Это **проверка размещения вызовов в исходниках**: замена классификатора константой может быть поведенчески эквивалентна на сегодняшнем допустимом диапазоне. Аналогично удаление отдельной проверки /24 не обязано проявиться поведенчески при сохранённой уникальности /16. Без контрпримера эти изменения не выдаются за квалифицированные semantic runtime mutants.

Отдельно остаются распределитель адресов/топологии, доказательства namespace/изоляции/source IP ядра, реальные identity, созданные узлами, readiness, независимый `MemberStart`, final accounting, restart, калибровка/ресурсный допуск, native CGO, воспроизводимость разных меток, тяжёлые сценарии и активация G2. Существующие loopback-only конфигурация дочернего узла, функциональные SDK overrides, граница корреляции Observe и поведение `FinalUnavailable` не меняются.
