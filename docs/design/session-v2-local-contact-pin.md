# K1: explicit Desktop contact provenance

## English

### Implemented scope

K1 connects an explicit Desktop contact-link import to a durable local-contact fact and subsequent genuine v2 proof. It does not implement K2 signed-record/min_session admission, its ingress queue/rate rules, operator K RPC, R/N-in, new dial intent, service priority, public identity-pin removal or release admission. There is no ten-minute wait for K. K is exempt from class quotas, but every unique identity still consumes the existing global 20,000-pin limit, including C3 restoration reservations. Existing pin classification takes no additional place; new identities at capacity are refused without eviction or automatic legacy fallback.

`DesktopClient.ImportContactLink` parses the link, then directly calls `Service.AddLocalContact` with typed network, identity and key material. The core verifies the configured network, nonzero/nonself identity, signing-key fingerprint and box binding again. No network frame, boolean, contact event, mutable Source field or old contact history grants this authority. Generic `import_contacts`/HTTP `importContacts`, incoming recovery, identity records and presence retain their existing behavior and produce no K local fact. The existing generic HTTP transport is unchanged. There is no TCP fallback or additional user confirmation for ordinary paste.

### Results and persistence

The typed result separates a contact applied to live memory, the local fact's durability and K classification. A late storage failure retains the applied identity/result; Desktop reports that the contact was added while durable K provenance is unsupported or unconfirmed. It does not report total import failure, discard the imported identity, or claim that an ordinary identity pin/other protection is absent. The K axis has explicit NotEvaluated, AwaitingFactConfirmation, AwaitingFreshProof, AwaitingPromotion, StagedUnconfirmed and Confirmed states. A captured proof waiting on fact I/O does not require an invented second proof. English and Russian UI messages have explicit English fallback in other locales.

Trust format 4 adds an optional version-1 fact inside the existing contact row: fact ID, network, exact identity and original local timestamp. Fact state uses immutable owned copies; there is no second identity map. Repeat explicit import preserves a surviving fact. Delete/re-add gets a new fact ID/runtime revision. Generic refresh/record Source changes preserve the fact. Genuine old formats without the field migrate with no inferred intent; unsupported schema, foreign/invalid authority and unknown fact fields refuse loading. A fact disguised in an older schema is refused. Existing decode failures remain fatal.

Loaded authority is authenticated before reuse by owner/permission audit and a pinned-directory, no-follow regular-file read with descriptor identity/content checks. A later strong rewrite cannot bless bytes originally read from an unsafe file. Unsafe loaded authority is refused without overwriting it. Valid loaded facts have no runtime ACK; unsupported durability defers their startup save and leaves them unusable for new K while the ordinary node remains usable. Other startup I/O errors preserve the existing fatal behavior.

An authorityObserved latch is set when any valid fact is loaded or staged, independently of ACK. It never clears during that store's lifetime. While latched, every ordinary and explicit snapshot uses the same strict root-relative writer under saveMu; there is no weak fallback after restart, unknown commit or contact deletion. Legacy/no-authority stores preserve their former ordinary writer/startup behavior. First-fact preflight precedes fact staging. Only DurableCommitted may ACK the exact current fact/revision; strict requests are forced even when an ordinary writer already saved that generation. NotCommitted, Indeterminate and errors do not assert rollback or unchanged disk bytes. Cancellation is checked after locks before new work; a completed namespace commit wins over later cancellation. Filesystem calls are not promised to be interruptible.

### Proof and lifecycle

Actual mandatory proof publication captures the pin entry binding within its original mutation, for inbound, outbound and noncanonical outbound cases. A successful opaque v2 proof may contribute K only when a matching explicit fact exists. One small runtime candidate belongs to that contact row and carries the original binding, proof and local-intent generation; it can wait for fact I/O. No later identity lookup, timestamp, TCP/legacy outcome or synthetic proof rebinds it. A contact imported after an earlier completed proof awaits a genuine new proof. Actual one-shot v2 proof can qualify; K does not depend on CM slot selection or continued ten-minute session age.

Before releasing the original apply/remember/known-set mutation section, the typed local path captures an exact runtime row-lifecycle stamp (store owner, identity and immutable nonzero-sized pointer marker). Only a genuine local apply mints/reuses the marker; generic refresh preserves it, while delete/recreate/restart resets it. The marker is JSON-ignored and is not durable authority. Preflight I/O remains outside the mutation mutex. Fact stage rechecks that exact row stamp after preflight/saveMu waits, before creating any fact/latch; a deleted original row returns stale even if generic import recreated the same identity/keys. ContactAppliedLive records the original historical effect and does not promise the replacement row has local intent. Existing fact-generation and original proof-entry incarnation checks remain independent.

Initial POSIX loading resolves legacy symlinks, pins the resolved parent and opens a regular file with the existing nonblocking/no-follow reader. It checks file identity/size before and after a size-plus-one limited read (overflow rejected); replacement/growth is refused without introducing a new file-size quota. These preliminary bytes are not trusted authority: facts additionally require owner/location audit of the original path and an exact protected reread limited to expected bytes plus one (overflow rejected) before confirmation. Windows retains the previous ordinary `os.ReadFile` path because its strict backend is unavailable; loaded facts remain unconfirmed, cannot be laundered through an ordinary weak save, and only the explicit unsupported durability error defers the startup self-row save. No Windows nonblocking-read or resource-admission claim is made.

The joined worker takes a transient identity inventory from the current capped pin owner (at most 20,000), releases its mutex and looks up only those contact rows. It has one coalesced wake channel and no growing identity-job queue. Generic contacts cannot enlarge this inventory. Unconfirmed facts without a qualifying proof retry on explicit import/new proof, not through a periodic unbounded contact-book scan. A required strict contact save still copies/encodes the full contact book: that I/O/memory cost depends on its size and is not a bounded D1 workload claim.

After backend I/O, the producer checks the exact durable local fact generation and original entry incarnation. C3 deletion/recreation invalidates the old binding; no old proof attaches to a replacement entry. A fresh later proof may repin and re-earn K. Metadata is staged through the pin owner CAS and independently confirmed by the existing strict full pin-snapshot writer. Ordinary writer success/memory staging is not that ACK. Failed confirmation retains historical staged K and ordinary protection without claiming confirmed K. Reproof preserves earned metadata. Contact deletion drops unearned intent but never strips an identity pin or already-earned historical K; current contact trust and future service priority remain separate.

C3 previews bind metadata/protection revisions; K staging invalidates an older preview without fabricating another transport proof. Full-entry backup/rollback/recovery retains K and all other allocations. Public C3 confirmation remains unavailable.

### Resource evidence

A 1,000-row fixture measured contact JSON growing from 489,038 to 745,933 bytes after local facts (+256,895), and pin JSON from 155,064 to 267,959 bytes after K metadata (+112,895). Heap samples are logged as observations and are affected by collection/pools; they are not attributed as stable per-record deltas. The unchanged original store-bound regression passed: file about 30.4 MiB, live structure 34.3 MiB under its 36-MiB guard, save about 95.6 MiB. ResourceBreakdown remains a documented structural floor: it includes both optional contact-row pointers, but excludes the allocated marker/fact/proof pointees, pin metadata, allocator/map overhead and transient full snapshots. The lifecycle marker adds one row pointer (8 bytes on 64-bit) and a one-byte nonzero-sized allocation for each row actually touched by the typed local path, excluding allocator/alignment cost. Immutable snapshot copies share this marker safely. The fixture separately logs marker/fact/proof structural allocation sizes. No unbounded contact-book metrics scan is added. These fixtures do not establish whole-application/D1 resource acceptance or admit a release.

## Русский

### Реализованная область

K1 связывает явный импорт контактной ссылки в Desktop с durable локальным фактом и последующим настоящим proof v2. Инкремент не реализует K2 admission подписанной записи/min_session, его ingress queue/rate rules, операторский K RPC, R/N-in, новые DialIntent, приоритет обслуживания, публичное снятие identity pin или допуск выпуска. Десятиминутного ожидания для K нет. K освобождён от классовых квот, но каждая уникальная identity учитывается в общем пределе 20 000, включая restoration reservations C3. Классификация существующего pin не занимает второго места; новой identity при заполнении отказывают без eviction и автоматического legacy fallback.

`DesktopClient.ImportContactLink` разбирает ссылку и напрямую вызывает `Service.AddLocalContact` с типизированными network, identity и ключами. Core повторно проверяет сеть, ненулевую/не собственную identity, fingerprint signing key и box binding. Сетевой frame, boolean, событие контакта, изменяемый Source и прежняя история контактов такой authority не дают. Generic `import_contacts`/HTTP `importContacts`, входящий recovery, identity records и presence сохраняют прежнее поведение и не создают локальный факт K. Transport generic HTTP не меняется. TCP fallback и дополнительного подтверждения обычной вставки нет.

### Результат и сохранение

Типизированный результат различает контакт в живой памяти, durability локального факта и классификацию K. Поздняя ошибка хранения сохраняет identity и результат применения: Desktop сообщает, что контакт добавлен, а durable-происхождение K недоступно или не подтверждено. Он не выдаёт это за полный отказ импорта, не теряет identity и не утверждает отсутствие обычного pin/другой защиты. Ось K имеет явные NotEvaluated, AwaitingFactConfirmation, AwaitingFreshProof, AwaitingPromotion, StagedUnconfirmed и Confirmed. Захваченный proof, ожидающий fact I/O, не требует выдуманного второго proof. Есть EN/RU UI-тексты и явный английский fallback остальных локалей.

Trust format 4 добавляет необязательный факт версии 1 в существующую строку контакта: fact ID, network, точную identity и исходный локальный timestamp. State использует immutable owned copies; второй identity map нет. Повторный явный импорт сохраняет существующий факт. Delete/re-add создаёт новый ID/runtime revision. Generic refresh и изменение Source записью сохраняют факт. Настоящие старые форматы без поля мигрируют без выдуманного намерения; неизвестная schema, чужая/повреждённая authority и неизвестные поля факта запрещают загрузку. Факт, скрытый в старой schema, отвергается. Прежние decode errors остаются fatal.

Загруженная authority проверяется до повторного использования: owner/permission audit, чтение обычного файла через pinned directory с no-follow и проверкой descriptor identity/содержимого. Поздняя строгая перезапись не легализует байты из исходно небезопасного файла. Небезопасная authority отвергается без перезаписи. Корректные загруженные факты не имеют runtime ACK; неподдерживаемая durability откладывает startup save и запрещает новый K, сохраняя обычную работу узла. Другие startup I/O errors сохраняют прежнее fatal-поведение.

Latch authorityObserved устанавливается при загрузке или staging любого корректного факта независимо от ACK и не снимается до конца жизни store. После этого обычные и явные snapshots используют один strict root-relative writer под saveMu; слабого fallback после restart, неизвестного commit или удаления контакта нет. Старые stores без authority сохраняют прежний ordinary writer/startup. Preflight первого факта предшествует staging. Только DurableCommitted подтверждает точный текущий факт/revision; strict request принудителен даже после обычного сохранения этой generation. NotCommitted, Indeterminate и ошибки не обещают rollback или прежние disk bytes. Отмена проверяется после locks до новой работы; завершённый namespace commit сильнее поздней отмены. Прерываемость filesystem calls не обещается.

### Proof и lifecycle

Настоящая mandatory-публикация proof захватывает binding pin entry внутри исходной мутации для inbound, outbound и noncanonical outbound. Успешный opaque v2 proof даёт основание K только при совпадающем явном факте. Один небольшой runtime candidate принадлежит строке контакта и содержит исходный binding, proof и поколение local intent; он может ждать fact I/O. Поздний identity lookup, timestamp, TCP/legacy outcome и synthetic proof его не перепривязывают. Контакт, импортированный после прежнего завершённого proof, ждёт новый настоящий proof. Подходит настоящий one-shot v2 proof; K не зависит от CM selection или десятиминутной живой сессии.

До освобождения исходной секции apply/remember/known-set mutation типизированный local path захватывает точный runtime stamp lifecycle строки (store owner, identity и immutable pointer marker ненулевого размера). Только настоящее локальное действие создаёт/переиспользует marker; generic refresh сохраняет его, delete/recreate/restart сбрасывают. Marker не сериализуется и не является durable authority. Preflight I/O остаётся вне mutation mutex. Fact stage повторно проверяет этот stamp после preflight/saveMu wait до создания факта/latch: удаление исходной строки даёт stale даже при generic readd той же identity/ключей. ContactAppliedLive обозначает исходный исторический эффект, а не обещает local intent новой строки. Проверки fact generation и исходной proof-entry incarnation остаются независимыми.

Начальная загрузка POSIX разрешает legacy symlink, закрепляет resolved parent и открывает обычный файл существующим nonblocking/no-follow reader. Проверяются identity/размер файла до и после чтения с пределом исходный размер +1 (overflow отклоняется); замена/рост дают отказ без новой size quota. Эти начальные байты не являются доверенным authority: для фактов дополнительно нужны owner/location audit исходного пути и точное защищённое повторное чтение с пределом ожидаемые байты +1 (overflow отклоняется). Windows сохраняет прежний ordinary `os.ReadFile`, поскольку strict backend недоступен: загруженные факты остаются unconfirmed, не получают authority через слабое обычное сохранение; только явный unsupported durability error откладывает startup self-row save. Nonblocking-read/ресурсный допуск Windows не утверждается.

Joined worker снимает временный inventory identity только из текущего ограниченного pin owner (не более 20 000), освобождает его mutex и читает лишь соответствующие contact rows. Есть один coalesced wake channel, растущей очереди identity jobs нет. Generic contacts inventory не расширяют. Неподтверждённые факты без подходящего proof повторяются по явному импорту/новому proof, а не периодическим неограниченным обходом address book. Нужное строгое сохранение контактов всё ещё копирует и кодирует всю книгу: его I/O/memory cost зависит от её размера и не является утверждением bounded D1 workload.

После backend I/O producer проверяет точное поколение durable local fact и исходную incarnation entry. C3 delete/recreate отменяет старый binding: старый proof не прикрепляется к новой entry. Позднее настоящее proof может снова создать pin/K. Metadata проходят pin owner CAS и независимый strict full pin-snapshot ACK. Успех обычного writer/staging в памяти не является этим ACK. Неудачное подтверждение сохраняет исторический staged K и обычную защиту без утверждения confirmed K. Reproof сохраняет заработанные metadata. Удаление контакта удаляет незаработанное намерение, но не identity pin/исторический K; текущее доверие и будущий service priority остаются отдельными.

C3 preview связывает metadata/protection revisions; staging K отменяет прежний preview без имитации нового transport proof. Full-entry backup/rollback/recovery сохраняют K и остальные allocations. Публичный confirm C3 остаётся недоступным.

### Ресурсные измерения

Fixture на 1000 строк дал рост contact JSON с 489 038 до 745 933 байт после фактов (+256 895), pin JSON — со 155 064 до 267 959 после K metadata (+112 895). Heap samples записаны как наблюдения, зависят от GC/pools и не выдаются за устойчивую стоимость одной записи. Неизменённый исходный store-bound regression прошёл: файл около 30,4 МиБ, живая структура 34,3 МиБ под guard 36 МиБ, save около 95,6 МиБ. ResourceBreakdown остаётся документированным структурным минимумом: включает оба optional-указателя contact row, но не выделенные объекты marker/fact/proof, pin metadata, allocator/map overhead и временные полные snapshots. Lifecycle marker добавляет указатель в строке (8 байт на 64-bit) и одно однобайтное выделение ненулевого размера для строки, затронутой typed local path, без allocator/alignment cost. Immutable snapshot copies безопасно разделяют marker. Fixture отдельно пишет структурные размеры marker/fact/proof. Не добавлен неограниченный metrics-обход книги контактов. Эти fixtures не утверждают ресурсный допуск всего приложения/D1 или выпуска.
