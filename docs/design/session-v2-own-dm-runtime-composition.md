# Inactive original Runtime composition: Ready and own-DM R

This candidate joins the existing Ready construction and charged-R own-DM producer on one `serviceConstruction`. It creates one Service, original runtime domain, publisher, trust store, secure store and run context. The original R2 port is minted after the resolver exists and before Ready checks, statistic installation, Seal and escape. Ready snapshots the exact port/owner/resolver/admission/profile holder and checks it again at finalization. The old isolated candidate remains available; its sole mint is shared, not duplicated.

`NewInactiveOwnDMRuntimeCandidate` takes explicit internal parameters and returns the paired Service/port plus a bound cleanup of the original lifecycle and background admission. It does not add a D1 activation flag or deployment defaults. SDK `newWithOwnDMRuntime` chooses it inside the same `newWithContext` body used by public `NewWithContext`. The public wrapper passes nil. The typed Desktop constructor validates original Service/identity before construction and installs DMCrypto before NodeProber, message-store registration or return. SDK sends still use `Runtime.SendDirectMessage`, its operation lease/context, real encryption, SQLite and original route. There is no second worker, new receipt factory, alternate Runtime, late enabling setter or observer-driven resend.

The SDK keeps two cancellation scopes for a typed own-DM send. Its operation context still governs encryption, SQLite, dispatch and the shutdown operation drain; the SDK releases and cancels that derived context when the method returns, including success. Optional R residence retains the original caller's cancellation/deadline separately and remains bound to the same original Service lifetime. Successful return therefore does not itself revoke pending residence or stand in for the original writer ACK. Explicit caller cancellation, original caller deadline, original Service shutdown, or the existing residence/TTL expiry still refuse unearned R. The origin is captured once at Node Submit; operation cleanup, queueing and ACK do not renew it or extend any timing limit. Ordinary one-context Node/DMCrypto entry points pass the same context for both scopes and keep their existing cancellation semantics. This separation adds no activation or public default.

Constructor error/panic cleanup cancels the original prepared Node lifetime and closes its existing background admission before background joins and database release. Ordinary Close uses its existing operation/router drain, then cancels Node through the existing started-Run path, lets Run close admission in its last defer, joins Run/background owners, and closes SQLite last. Closing before Start invokes the bound original cancel+gate-close cleanup before the background join. The normal nil-profile Runtime receives the same construction-owned cleanup; no exported Service method or RPC surface is added.
