# Неактивное хранилище owned pending/correlation

Приватный intakeCoordinator хранит один отдельно созданный candidatePendingBook: разреженный массив512 указателей pendingEntry, исходный mutex и прежнее неактивное диагностическое состояние. Публичный PendingTable с четырьмя map и его API не изменён. Активация Node/bridge, Ready/Seal, новый профиль или полномочие окончательного admission не добавлены.

Поиск source использует исходный Session и ID запроса. Correlation требует исходный target Session, forwarded ID и фазу Reserved/Dispatching/AwaitingAnswer. Provisional и TerminalDispatch не коррелируют, однако все физические указатели учитываются в пределах512/16наSession/16наtarget. Ответ или end при незавершённом writer сохраняет TerminalDispatch до единственного Finish. Освобождение ячейки не обнуляет и не переиспользует entry/intake и не возвращает projected/actual debt source/group/calendar. Совпадение ключа или ячейки не оживляет старый handle.

Порядок блокировок owner->pending->одинcalendar->targetID сохранён. До последнего fallible fresh sourceWindows CAS проверяются локальный индекс точного entry, конфликт targetID, окончательная capacity и все исходные checked trials. Тот же pending mutex удерживается непрерывно; forwarded+Reserved публикуют correlation без map insertion, allocation, callback, нового ожидания mutex, часов или fallible проверки в новом suffix. Индекс не сохраняется в handle. Offer определяет vacancy или допустимую provisional жертву до замены; принятые writer obligations не являются жертвами. Полный sparse обход не пропускает соседние удаляемые строки.

Тестовый frozen reference с четырьмя map получает только законно допущенные исходные owner events. Его raw release сохраняет старое удаление по ключу и не вызывается для detached stale entry. Защитный fixed.release проверяется отдельно; реальные stale cancel/permit/Finish сохраняют полное сравнение неизменённого состояния. Два прежних некорректных fixture заменены настоящим физическим TerminalDispatch, мешающим retirement, и отдельной действительно committed correlation с явно тестовым rewind ID. Точные ErrStaleWork/ErrDuplicateID/ErrCapacity и полные accounting/DeepEqual проверки сохранены. Новый tie-break вместо старого множества допустимых порядков не вводится. Устаревшие cancel/Take сначала продвигают время владельца, затем проверяют reservation. Поэтому ABA-проверки отсутствия дополнительного изменения сначала завершают законный sweep на том же now, требуют живые исходные Session и отсутствие строк, подлежащих expiry, и проверяют идемпотентность повторного sweep сравнением полного accounting. Для произвольного более позднего времени отсутствие изменений не обещается; production-порядок advance-before-stale сохранён.

Устраняются только динамические authoritative pending/count/correlation map owned owner. Временные workbooks sealRound/prepareSources, подготовка новых row/calendar/slot/companion, непрерывная same-domain read lease, полные original cut/point/time/capacity проверки, доказательства actual allocation/escape/resources и совокупные пределы retained handles остаются отдельной работой C2d2/C3. SOURCE тесты и виртуальные causal recipes не запускались и не являются принятой QA.
