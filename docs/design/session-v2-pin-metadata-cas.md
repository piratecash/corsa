# Identity-pin metadata owner CAS preparation

## English

This C5-2A increment prepares an internal concurrency primitive. It enables no class producer, quota, session-age rule, service priority, new dial consumer, public endpoint or release admission. It does not select the future C5-2B class policy. The [format-2 storage and full-entry recovery contract](session-v2-pin-metadata.md) remains unchanged.

`secureSessionStore.identities` remains the sole live owner. Every accepted new entry receives a fresh nonzero runtime protection revision from the store's monotonic sequence. Reproof of an existing valid entry advances only its proof revision and preserves its protection revision and metadata. A metadata change advances the protection revision without pretending that another proof occurred. Creating an entry preflights both counters before either changes; metadata staging checks its own counter before changing the entry or dirty generation. Exhaustion fails closed without wrapping. Exhaustion of the protection sequence does not prevent reproof of an already valid existing entry.

Removal previews bind both revisions and the metadata value. Consequently A → B → A does not revive an old preview even when the final bytes equal the original metadata. Updating one identity leaves another identity's token valid. The counters are runtime-only: neither the main-file format, full backup, guard nor broker permit gains a revision field. Restart still changes the preview key.

The private `pinMetadataSnapshot` is a value copy stamped with its owner store instance, identity, nonzero proof revision and nonzero protection revision. A zero stamp, foreign store, prior process instance, changed proof, changed metadata or removed/recreated entry cannot authorize a CAS. An unchanged desired value is accepted only after the current stamp is validated. Metadata values and unpublished entry copies retain the existing copy-on-write ownership; a caller or old snapshot cannot mutate the published entry through an alias.

`stagePinMetadata` is deliberately **memory-only**. Under `pinMutationGate.RLock → mu` it validates the stamp, copies metadata into an unpublished entry value, advances the protection sequence and increments the existing dirty generation atomically. It refuses an unreadable store or fatal recovery state. A changed result is `StagedUnflushed`; an equal result is `UnchangedInMemory`, with no counter or dirty-generation change. Neither result asserts that any metadata is on disk. The operation performs no I/O, does not acquire `writeMu`, takes no cancellation context and offers no disk-I/O cancellation guarantee. It can wait for the existing mutation gate; it is not an admission or publication barrier for a future session.

Raw `setUnpublishedMetadata` is restricted to constructing an unpublished entry copy: load, absent-entry recovery, and the owner CAS itself. It is not a live-producer mutation API. A future producer must use the owner primitive and obtain a separately reviewed persistence/admission contract before treating its result as durable protection or class eligibility.

The ordinary writer can subsequently persist staged metadata, including from an unrelated flush. An earlier snapshot's `covers` generation must not mark later metadata as written; the existing serialized writer and dirty/written counters retain that rule. A failed write leaves staged memory dirty and may already have changed the on-disk file. This primitive does not roll memory back, certify the old disk contents or classify the writer's uncertain commit outcome. Retrying the existing writer can cover the dirty generation. Cancellation, definite/uncertain write outcomes and publication after durable admission belong to the future producer contract; no destructive C3 fence or network-stop behavior is added here.

Tests cover value-only ABA with a deterministic failing control, stale/foreign/zero stamps, proof versus protection revision semantics, counter exhaustion before effects, removal and recreation, restart, mutation versus the actual C3 removal gate, alias isolation, staging during an endpoint flush, and a real write followed by an injected error. The unchanged 36 MiB live-store bound remains required. The current unclassified-pin fixture measured approximately 30.4 MiB on disk, 34.1 MiB live and 95.4 MiB during save after adding the runtime revision. These tests do not admit a class policy or establish a D1 resource budget.

The subsequent [C5-2B1 Selected producer](session-v2-selected-pin-promotion.md) adds a separate context-aware class-admission path and strict snapshot acknowledgment. It does not turn the generic memory CAS result into durability evidence.

The [inactive N-in journal core](session-v2-inbound-pin-journal.md) closes generic CAS changes to Inbound: those require one paired allocation/debit operation. Existing unpublished validated load/recovery remains distinct and does not debit. Other COW changes preserve Inbound and K2 owner/mirror; their historical ACK is not confirmation of a newer metadata revision. This adds no live N-in producer.

## Русский

Инкремент C5-2A подготавливает внутреннюю операцию управления конкурентностью. Он не включает producers классов, квоты, правила возраста сессии, приоритет обслуживания, новые dial consumers, публичный endpoint или допуск выпуска. Будущая политика классов C5-2B здесь не выбирается. [Контракт формата 2 и полного восстановления записи](session-v2-pin-metadata.md) не меняется.

Единственный живой владелец остаётся `secureSessionStore.identities`. Каждая принятая новая запись получает новую ненулевую runtime protection revision из монотонной последовательности хранилища. Reproof существующей корректной записи повышает только proof revision, сохраняя protection revision и metadata. Изменение metadata повышает protection revision, не изображая новое доказательство. Создание записи проверяет оба счётчика до изменения любого из них; staging metadata проверяет свой счётчик до изменения записи и dirty generation. Исчерпание закрывает операцию отказом без переполнения. Исчерпанная protection sequence не препятствует reproof уже существующей корректной записи.

Preview снятия связывает обе ревизии и значение metadata. Поэтому A → B → A не возвращает прежнему preview валидность, даже если итоговые байты совпали с исходными metadata. Изменение одной identity сохраняет валидность token другой identity. Счётчики существуют только в runtime: основной формат, полный backup, guard и broker permit не получают нового поля ревизии. Restart по-прежнему меняет ключ preview.

Внутренний `pinMetadataSnapshot` — копия значения со stamp экземпляра хранилища, identity, ненулевой proof revision и ненулевой protection revision. Нулевой stamp, чужой экземпляр, прежний процесс, изменённое доказательство, изменённые metadata и удалённая/повторно созданная запись не разрешают CAS. Равное желаемое значение принимается только после проверки текущего stamp. Значения metadata и неопубликованные копии entry сохраняют copy-on-write ownership: caller или прежний снимок не меняет опубликованную запись через alias.

`stagePinMetadata` намеренно работает **только в памяти**. Под `pinMutationGate.RLock → mu` он проверяет stamp, копирует metadata в неопубликованное значение entry, повышает protection sequence и атомарно увеличивает существующую dirty generation. Нечитаемое хранилище и fatal recovery запрещают операцию. Изменение возвращает `StagedUnflushed`; равное значение — `UnchangedInMemory` без изменения счётчиков и dirty generation. Ни один результат не утверждает наличие metadata на диске. Операция не делает I/O, не берёт `writeMu`, не принимает cancellation context и не гарантирует отмену disk I/O. Она может ждать существующий mutation gate; это не барьер admission или публикации будущей сессии.

Raw `setUnpublishedMetadata` предназначен только для построения неопубликованной копии записи: load, recovery отсутствующей записи и сам owner CAS. Это не mutation API живого producer. Будущий producer обязан использовать owner primitive и отдельно проверенный контракт persistence/admission до трактовки результата как durable protection или классовой eligibility.

Обычный writer может позднее сохранить staged metadata, в том числе при постороннем flush. Generation `covers` более раннего снимка не должна помечать позднейшие metadata сохранёнными; существующие сериализованный writer и счётчики dirty/written сохраняют это правило. Неудачная запись оставляет staged memory грязной и уже могла изменить файл на диске. Primitive не откатывает память, не подтверждает прежнее содержимое диска и не классифицирует неопределённый commit writer. Повторный вызов существующего writer может сохранить dirty generation. Отмена, определённый/неопределённый результат записи и публикация после durable admission относятся к будущему контракту producer; destructive C3 fence и остановка сети здесь не добавляются.

Тесты покрывают value-only ABA с детерминированным падающим контролем, устаревшие/чужие/нулевые stamp, отдельную семантику proof и protection revisions, исчерпание до побочных эффектов, удаление и повторное создание, restart, mutation против настоящего C3 removal gate, alias isolation, staging во время endpoint flush и настоящую запись с последующей внедрённой ошибкой. Прежний предел живой памяти хранилища 36 МиБ остаётся обязательным. Текущий fixture с unclassified pin после добавления runtime revision дал примерно 30,4 МиБ файла, 34,1 МиБ живой структуры и 95,4 МиБ при сохранении. Эти тесты не разрешают классовую политику и не утверждают ресурсный бюджет D1.

Последующий [producer Selected C5-2B1](session-v2-selected-pin-promotion.md) добавляет отдельный context-aware class-admission path и strict snapshot acknowledgment. Это не превращает результат общего memory CAS в доказательство durability.

[Неактивное ядро журнала N-in](session-v2-inbound-pin-journal.md) запрещает общий CAS для изменения Inbound: требуется одна парная операция allocation/debit. Прежние unpublished validated load/recovery остаются отдельными путями без нового дебета. Остальные COW изменения сохраняют Inbound и K2 owner/mirror; исторический ACK не подтверждает новую metadata revision. Live N-in producer это не добавляет.
