# D1 owned registry publication candidate

This conditional implementation keeps the original immutable publisher attached before the first Service literal. Ordinary constructors have no attachment and allocate no registry publication. The private owned root remains Constructing: this slice installs neither Ready, a complete reader/cut, public controls nor activation.

The registry/provenance family contains fourteen functions and fifteen local nonclock publication branches. Existing peerMu, deliveryMu, common and readiness waits precede W. Each branch owns its publication locally and completes immediately after its fixed memory mutations, before another lock, callback, logging, clock, Close or I/O. The ordinary nil branch checks the publication before calling Complete: the leaf API deliberately rejects Complete on nil. Map operations may allocate or encounter runtime scheduling/GC; no latency or resource bound is asserted.

The inbound/outbound registry insertions publish both original indices together. Original transport attachment publishes the checked entry/common/ConnID reciprocity, then performs independent N-in binding outside W. CM receipt preparation allocates before W, under the same peerMu as the actual generation-accepted callback. Only that callback stores selectedGeneration and a prepared nonnil receipt. An invalid preparation keeps the old receipt, matching previous behavior. The later F1 publication still checks the complete original tuple, authentication, role, exact entry/current Session and accepted generation.

Unregister retains peerMu, resolves the original secondary key, finishes original common End, closes the original receive state and releases its budget. Only then does a separate registry W remove the two indices. End independently owns common → degree → clock → W; an outer registry W around End would deadlock. Cancellation, clock poison and unavailable observation never veto mandatory cleanup. A capture between End and removal can see terminal state, and removal invalidates that intermediate generation. S2 supplies no complete capture algorithm.

Session map publication preserves existing semantics. CM removal retains its exact Session pointer predicates, so late A cleanup cannot remove current B. The legacy address-only runPeerSession and ensurePeerSessions cleanup is unchanged and does not gain that guarantee. Replacing a map pointer introduces no automatic End policy. ConnID exhaustion/reuse policy is not supplied here.

Tests use genuine TLS proof/common/P1 fixtures for original F1 End and cancellation/poison cleanup. The paired-map insertion oracle uses an explicitly non-proof core so a preceding common/P1 publication cannot mask a missing insertion publication. The deletion oracle takes its second stamp after End, isolating deletion. The CM A/B ownership fixture retains genuine proofs/degree origins and fixes only the original server LocalAddr before TLS construction to provide one controlled dial-address key; it claims no B accepted receipt or published F1. The existing S1 actual-CM fixture still exercises accepted receipt/postsetup F1. Its test-only dispatch is owned and joined asynchronously when the test holds W; production CM callbacks stay synchronous.

SOURCE guards freeze the fifteen helper reference/call roles, thirteen direct registry/session mutation sites, twenty-seven explicit compact-raw function-body pins, and existing strict importer/publication/receipt inventories. They are finite syntax contracts, not typed whole-program alias analysis. Nested-W, early/concurrent completion, allocation or callbacks inside W remain SOURCE controls where no legitimate deterministic functional seam exists; deliberate deadlock mutants are not executed. Future FORMAT/TYPE/ordinary/race qualification is required. Existing negative categories remain independent obligations.

The degree origin inventory remains 100 physical rows/92 keys. Exactly one new leaf importer, conn_registry.go, expands the approved set from eight to nine; the pin/trust API inventories gain the single beginRegistryPublication row. RAW construction pins retain their raw SHA256 algorithm and the same thirty-six paths. The changed find_node_connection.go pin and the exact publishAcceptedProofTransport common.Lock stack line are explicitly rebound in SOURCE; all thirty-six hashes and that same callsite require independent readback after actual formatting.

Full writer/read/cut closure, other core/auth/tracked metadata, admission, production Ready/Seal, G2, resource acceptance, activation and release remain open. These files do not establish completion of D1.
