# Linux process-observation foundation

## English

This is a functional T5 foundation. It adds no production runtime wiring, Linux node launcher, namespace orchestration, resource acceptance, baseline/candidate measurement, or D1 approval. The existing macOS loopback `Provenance` keeps both verification flags false. A successful `LinuxProcessSampler.Sample` returns a separate verified observation only after its actual checks.

`ReadLinuxIncarnation` observes PID/start ticks under the nonzero target UID. `OpenLinuxProcess` requires that incarnation, the same UID, an independently supplied expected SHA-256 and an explicit maximum executable size (at most 128 MiB). A future launcher must retain its owned child lifecycle while obtaining this expectation; an arbitrary supplied PID is not proof of launch ownership. Expectations are ephemeral within one run and PID namespace, not restart credentials. Hash equality does not prove configuration, arguments, or uninterrupted execution history.

The sampler opens trusted `/proc` once, checks procfs and its root owner/mode, and checks that `self` resolves to its own PID view. It retains the PID directory descriptor; reads never reopen a process by pathname after that binding. A descriptor for a dead process cannot act on a new holder of its PID. This is the kernel's documented [procfs descriptor behaviour](https://docs.kernel.org/filesystems/proc.html). Root, mounts and the kernel are trusted; the node has no mount capabilities. Another proc mount/PID namespace cannot supply an interchangeable expectation.

Before and after collection, the sampler checks PID/start ticks, live state, all four target UIDs, and the actual `exe` descriptor. It hashes the opened regular ELF with bounded buffers/total size and checks descriptor metadata before/after reading. It never reopens readlink text or substitutes the launch-path hash. Changed, missing, dead or inaccessible identity/executable state fails the whole observation; no previous sample is returned as fresh. Concurrent `Close`/`Sample` serialize on one mutex. An explicit uninitialised/open/closed state prevents a zero-value handle from closing unrelated descriptors. Context is checked between reads: it cannot interrupt a kernel-blocked file operation. An unresponsive helper requires owned-container termination and a defective run; it cannot produce graceful success.

CPU output preserves process user/system ticks and explicit frequency availability. Frequency comes from `AT_CLKTCK` in the helper's auxiliary vector, whose [Linux UAPI number is 17](https://raw.githubusercontent.com/torvalds/linux/master/include/uapi/linux/auxvec.h); no frequency is guessed. Nanosecond conversion checks overflow. Status reports VmRSS, VmHWM and RssAnon in bytes, converting reported kB by 1024; these kernel RSS observations are not exact live heap cost. Descriptor enumeration is bounded to 65536 names. Missing, malformed, unreadable or oversized metric data remains explicitly unavailable, distinct from a measured zero.

Scheduler output declares `leader_thread` scope. It is not a sum over Go threads. The sampler requires a positive `sched_schedstats` check on both sides of the read before reporting scheduler values. If that switch is disabled, absent or unreadable, all scheduler values are unavailable. This conservatively refuses the all-zero disabled stub emitted by [the kernel proc implementation](https://raw.githubusercontent.com/torvalds/linux/master/fs/proc/base.c). External samples explicitly lack wait ownership. The functional helper alone uses its single `Cmd.Wait` result to report final normal-exit wait4 usage, including Linux high-water RSS units; the future launcher still owns that integration.

The concrete functional helper executes under UID 10001, sets itself nondumpable, makes its private control channel close-on-exec and starts the target under that same UID with no inherited control descriptor. An ordinary target exec is checked dumpable; `RLIMIT_CORE=0` remains enforced. The helper owns child signals and the only wait. Its child has kernel parent-death SIGKILL; the helper locks the spawning OS thread through child reaping. A deliberate helper self-exit control confirms the old child is dead or gone. Parent EOF triggers TERM and bounded kill fallback, then reaping. Root without `CAP_KILL` cannot substitute for this ownership. A stalled helper is an owned-container defect, not grounds for adding capabilities.

The native linux/arm64 control ran under `scripts/heavy-run.sh`, in a cached Alpine image `sha256:33bee74c45f307e3268adc2010c0f55c48e7a6041e12cd12432bb1a46e498e43`, with label `corsa.loadstand`, network none, a read-only root, 16 MiB noexec tmpfs, two CPUs, 768 MiB, PID limit 64, default seccomp, no-new-privileges, cap-drop ALL and only SETUID/SETGID added. It exercised actual exe/start/status/fd/clock readings; wrong start/hash/UID/size; cancellation; nondumpable denial/recovery; private control; EOF/drain/wait4; helper death; uninitialised, dead and closed handles. The executable basename contains `) (` to exercise kernel stat comm parsing. An earlier feasibility probe confirmed executable access but exposed root's missing signal permission; only its own labelled container was stopped, and that probe is not reported as a passing lifecycle test. No foreign containers were changed, packages/images downloaded, extra capabilities added, or heavy measurements run.

## Русский

Это функциональная основа T5. Production wiring, Linux launcher, netns orchestration, приёмка ресурсов, A/B-замеры и D1 approval не добавлены. Прежний macOS loopback `Provenance` сохраняет оба verification flags равными false. Отдельный `LinuxProcessSampler.Sample` выдаёт verified observation только после фактических проверок.

`ReadLinuxIncarnation` читает PID/start ticks под ненулевым UID цели. `OpenLinuxProcess` требует этот incarnation, тот же UID, независимо заданный SHA-256 и явный предел executable не больше 128 МиБ. Будущий launcher должен удерживать lifecycle своего child при получении ожидания: произвольный PID не доказывает владельца запуска. Ожидания действуют только внутри одного прогона/PID namespace. Хеш не доказывает конфигурацию или непрерывную историю исполнения.

Открываются проверенный procfs root и постоянный PID directory FD. Операции с descriptor умершего процесса не переходят к новому владельцу PID; это [контракт ядра procfs](https://docs.kernel.org/filesystems/proc.html). Root, mounts и ядро входят в доверенную границу; у узла нет mount capabilities. До и после сбора сверяются живой PID/start, все четыре UID и настоящий `exe` FD. Хешируется открытый regular ELF с пределом размера и проверкой metadata; launch-path/readlink не переоткрываются. Ошибка identity/executable означает отказ всего observation без возврата старых данных. Close и Sample сериализованы. Context проверяется между чтениями, но не прерывает зависший kernel I/O; зависший helper требует остановки собственного контейнера и дефекта прогона.

CPU сохраняет ticks и доступность частоты из AT_CLKTCK, без предположения «Linux = 100». Пересчёт в наносекунды проверяет overflow. VmRSS/VmHWM/RssAnon переводятся из kB в байты; это не точная стоимость heap. FD enumeration ограничен 65536 именами. Отсутствующее, некорректное или нечитаемое значение явно unavailable, а не ноль. Scheduler помечен `leader_thread`, без суммы Go threads; если sched_schedstats не подтверждён как включённый до и после чтения, все scheduler values unavailable, включая возможный нулевой stub ядра. Внешний sampler не владеет wait. Только функциональный helper использует единственный Cmd.Wait для final normal-exit wait4; integration launcher остаётся отдельной работой.

Настоящий helper под UID 10001 устанавливает себе nondumpable, закрывает control FD на exec и запускает child под тем же UID. Target проверяет обычный dumpable exec и RLIMIT_CORE=0. Child не наследует control FD и не может получить его через `/proc/helper/fd`. Helper владеет TERM/KILL и единственным Wait; EOF родителя завершает и reap-ит child. Root без CAP_KILL не заменяет эту роль. Зависание helper означает дефект и остановку собственного контейнера, не увеличение capabilities.

Проверка linux/arm64 прошла под существующим heavy-run lock на указанном выше cached image: network none, read-only root, tmpfs 16 МиБ/noexec, 2 CPU/768 МиБ/64 PID, default seccomp, no-new-privileges, cap-drop ALL и только SETUID/SETGID. Проверены настоящие метрики и ELF, неверные ожидания, cancellation, потеря/возврат доступа, private control, EOF/Wait4, dead/closed handle. Basename с `) (` проверяет stat comm. Предварительный probe выявил запрет сигналов root→другой UID; остановлен только собственный labelled контейнер, lifecycle PASS ему не приписывается. Посторонние контейнеры не затронуты, загрузок и тяжёлых замеров не было. Стоимость helper/sampler не выдаётся за стоимость узла.

Состояния sampler uninitialised/open/closed явно различаются: нулевой handle не закрывает посторонние FD. Child получает kernel parent-death SIGKILL, а OS thread helper закреплён от Start до reaping. Контроль настоящего self-exit helper подтверждает остановку прежнего child.
