# D1 local target in Node

The dedicated local-target constructor binds one responder calendar to the same
original intake, observer and consumer before the Service escapes. It also
constructs a bounded local signing queue. Ordinary constructors remain inactive.
The candidate remains Constructing; this change does not seal the runtime or
select a release resource profile.

The original read lane records the successful receive point before command
admission and Node waits. After strict parsing and a complete original Node
observation, a request for this node takes the local branch before remote
neighbor selection. A request for a different identity still requires that exact
known live neighbor. Unknown identities receive no response; recursive routing
belongs to a later protocol stage.

Node claims a bounded queue slot before local core admission. One mutex orders
reservation and enqueue so accepted projected signing slots reach the worker in
calendar order. The slot covers queue residence and signing, and the single
worker uses one timer. A full queue or a closed background gate therefore
refuses before an accepted local obligation exists. Shutdown cancels pending
original work and drains the same bounded queue under its admission mutex.

A timer only schedules a new attempt. The worker obtains a fresh hint and calls
`OwnedLocalSignWork.Take` after its waits. That Take is actual local AdmittedAtT;
it is distinct from forwarding writer Take and consumes the independent local
signing budgets. Transcript construction and cryptography run after Take has
released the core locks. A clock-only hint failure is terminal for that exact
pending work: invalid, ended or poisoned provenance has no transient Busy path.
The worker retires it without a new clock or refund. A lawful pre-T actual Take
refusal still retains the same accepted work and schedules a fresh attempt.
Every admitted signing attempt calls the original
permit's Complete, including errors and recovered signer panics. Completion does
not refund either actual budget.

Cached copies and successful completion return opaque answer work retaining each
original recipient, envelope ID and response expiry. Local and relayed answers
use the same answer queue and writer. Queue selection fixes the exact original
Session and concrete core; a later connection at the same numeric ID cannot
receive an earlier answer. The writer's fresh accepted clock check enforces the
original expiry without refreshing it to queue or completion time.

Local retirement is copied into the original connection binding alongside
forwarding retirement before F1 escape. Terminal publication keeps its existing
W/common ordering. After those locks release, both original owners receive the
same ended Session. End after T still permits mandatory signing completion,
while closed recipients cannot acquire answer work or borrow a replacement
connection.

This is an inactive integration candidate. Full construction closure, final
resource qualification, activation, public initiator behavior and D1 release
acceptance remain separate work. The only initiator needed for this stage is
the bounded protocol verification harness.
