# Process final accounting

## English

The functional process stand separates three facts: the normal SDK's joined transport, the sole waiter's owned-command exit/usage, and validation of a per-launch final report. This implements a finite T5 observation slice. It does not admit resource measurements, Linux namespaces, legacy comparisons, T6/T7, G2 or D1 completion.

`sdk.Runtime.FinalTransport()` returns a copied immutable snapshot only after normal managed-CM construction, a completed node start, and every required `Close` join: SDK operations, router sends/loops, node Run (including managed CM/bootstrap/session readers and NetCore writers), node background work, event bus and router drain. Its `ReadAt` is latched once. Never-started, failed-before-node and incomplete shutdowns remain unavailable. A later successful Close retry may make the observation available without rewriting the first `Wait` error. Quiescent transport remains a separate fact if the subsequent database close fails; such a child still cannot produce a successful strict final report.

Each successful spawn has one `Cmd.Wait` owner and one signal watcher. Explicit Stop and lifetime cancellation coalesce constant-size requests. The watcher records a signal attempt before calling Signal/Kill under the terminal gate. If the earliest known deadline elapsed before Reaped, ForceRequested is conservatively sealed even when the watcher has not processed its timer; ForceAttempted and signal success still require an actual syscall. Reaped prevents further signal admission; the waiter joins the watcher, copies typed exit/usage/close facts and publishes `Done`. The watcher never waits for Done. Lifetime cancellation preserves SIGTERM then five-second escalation. Stop preserves its caller deadline and two-second confirmation budget even if a previous Signal is held inside the gate. An unconfirmed return retains ownership and cannot be erased by later publication. No competing CommandContext/WaitDelay kill or second Wait4 exists.

`ProcessExitResult` contains copied values, no raw ExitError/ProcessState/error chain, mutable metric pointer, slice or map. Usage obtained from that same wait may remain measured after a signal exit, while strict transport finality is unavailable. Its scope is **owned_command**: a sandbox wrapper is not asserted to be the actual SDK PID. CPU/RSS are not descendant totals or resource acceptance.

The parent retains one `os.Root` from before launch. It exclusively creates the private nonce-named slot through that root and transfers its writer as FD3; the child duplicates that same inode once for scans. The child publishes only after SDK Wait and its receipt observer have joined, writes/syncs/closes the inherited writer and scans signing/box-key material and RPC credentials through the retained scan FD. The parent reads only after Done through the original root and original live pinned inode. A parent-only CLOEXEC duplicate stays open from construction through reduction or conclusive explicit cleanup, so an unlinked file cannot be confused with a recycled device/inode number after every child handle closes. Canceled reduction or unconfirmed Stop retains both root and pin; every conclusive/error cleanup closes them. No profile pathname is reopened to recover authority. Both actual-FD checks require regular file, effective owner, mode 0600 and acceptable ACL, before and after reading; the original directory requires mode 0700. FIFO/symlink/replacement/nonregular/oversize or unknown authority refuses. The report and its scan reads are bounded to 8 KiB. Context cancellation retains an unsealed capability for retry; it does not interrupt arbitrary kernel filesystem calls.

On Darwin+cgo, actual-FD `fstatx_np`/`filesec_query_property(FILESEC_ACL)` explicitly determines security-property presence. An errno from `acl_get_fd_np` alone is not proof of an absent ACL. A present ACL is validated, traversed with Darwin's native cursor/end convention and bounded entry count, and freed on every path. Grant/unknown ACEs refuse; deny-only entries do not weaken private mode. Native empty/allow/deny/API-error controls exercise real temporary FDs. See Apple's [ACL FD implementation](https://github.com/apple-oss-distributions/Libc/blob/main/posix1e/acl_file.c) and [entry iteration implementation](https://github.com/apple-oss-distributions/Libc/blob/main/posix1e/acl_entry.c). Darwin without cgo and unsupported platforms cannot supply this final-file authority. The Linux helper checks effective owner/private mode and the descriptor's POSIX access ACL; this does not implement a Linux namespace launcher or grant Linux resource admission.

Version 1 requires exactly ten canonical, non-null fields: `version`, `launch_nonce`, `plan_sha256`, `identity`, `started_at`, `read_at`, `bytes_sent`, `bytes_received`, `transport_quiescent`, `sdk_shutdown_outcome`. Duplicate, unknown, missing, case-alias, malformed, trailing, oversized or unsupported values refuse. Nonce and public launch-configuration/binary fingerprint correlate one launch; they do not attest effective config or executable provenance. Identity/start/ordinal authority comes from the independently completed member StartReceipt. Per-launch prior evidence consists only of two counter high-water marks and explicit binding/seen/invalid state; invalid evidence is sticky. A final report must dominate both high waters and assert quiescence and successful SDK shutdown.

Post-Done artifact reduction has a separate context-aware owner, never the terminal/member mutex. It seals a copied result without changing the sealed exit. Strict `FinalExact` requires completed-start binding, clean owned exit, successful child/observer/scanners/parent closes and a valid final report. Every other completed incarnation is unavailable with no counter value. `StopReceipt.Ended` is optional: failed starts cannot append a zero or historical incarnation. Unconfirmed termination retains process/root ownership; canceled reduction after confirmed exit also retains its owner for retry and is distinct from a kernel StopUnconfirmed. Returned ended observations are deep copies.

## Русский

Функциональный процессный стенд разделяет три факта: завершённый transport обычного SDK, exit/usage собственного command из единственного wait и проверку итогового отчёта конкретного запуска. Это конечный наблюдаемый срез T5; он не допускает ресурсные замеры, Linux namespace, сравнение legacy, T6/T7, G2 или завершение D1.

`sdk.Runtime.FinalTransport()` возвращает неизменяемую копию лишь после обычного создания с managed CM, завершённого запуска узла и всех обязательных join в Close: SDK operations, router sends/loops, Run узла (включая CM/bootstrap/session readers и NetCore writers), фоновых задач, event bus и router drain. ReadAt фиксируется один раз. Без Start, при отказе до запуска узла или незавершённом shutdown наблюдение unavailable. Успешный повтор Close может открыть наблюдение, не переписывая первый исход Wait. Ошибка последующего закрытия БД не отменяет отдельный факт quiescence, но такой child не выдаёт успешный strict final report.

После spawn существуют один владелец Cmd.Wait и один watcher сигналов. Stop и отмена lifetime объединяют запросы постоянного размера. Watcher фиксирует попытку до Signal/Kill под terminal gate. Если известный earliest deadline истёк до Reaped, фиксируется conservative ForceRequested даже до обработки timer watcher-ом; ForceAttempted и успех сигнала требуют настоящего syscall. Reaped закрывает допуск сигналов; waiter присоединяет watcher, копирует типизированные exit/usage/close facts и публикует Done. Watcher не ждёт Done. Сохраняются SIGTERM и эскалация через пять секунд, deadline Stop и две секунды подтверждения даже при удерживаемом Signal. Неподтверждённый исход сохраняет владение и не исчезает при поздней публикации. Конкурирующих CommandContext/WaitDelay kill или второго Wait4 нет.

ProcessExitResult содержит копии значений без raw ExitError/ProcessState/error chain, изменяемых metric pointers, slices или maps. Usage того же wait может быть измерен после signal exit при недоступной strict transport finality. Область **owned_command** не выдаёт sandbox wrapper за фактический SDK PID. CPU/RSS не являются суммой потомков или ресурсным допуском.

Родитель сохраняет один os.Root до запуска, эксклюзивно создаёт private slot с nonce и передаёт writer через FD3. Child один раз дублирует тот же inode для проверки. После SDK Wait и join receipt observer он записывает/sync/закрывает writer и проверяет signing/box-key material и RPC credential через scan FD. Родитель читает после Done через исходный root и живой pinned inode: parent-only CLOEXEC duplicate открыт от создания до reduction или подтверждённой явной очистки, поэтому переиспользованный после unlink device/inode не подменяет объект. Отмена reduction или неподтверждённый Stop сохраняет root и pin; подтверждённая/error cleanup закрывает оба, не открывая заново путь профиля. До и после чтения actual FD обязан быть regular file эффективного владельца с mode 0600 и допустимым ACL; directory требует 0700. FIFO, symlink, подмена, nonregular, oversize и неизвестная authority дают отказ. Отчёт и scan reads ограничены 8 КиБ. Отмена context сохраняет незавершённое владение для повтора, но не прерывает произвольный kernel filesystem syscall.

Darwin+cgo явно проверяет наличие ACL через actual-FD fstatx_np/filesec_query_property(FILESEC_ACL), а не трактует errno acl_get_fd_np как отсутствие ACL. Непустой ACL валидируется, обходится native cursor с правильным Darwin end convention и ограниченным числом записей; память всегда освобождается. Grant/unknown ACE запрещены, deny-only не ослабляет private mode. Настоящие temporary FD проверяются для empty/allow/deny/API-error. Первичные реализации Apple [ACL FD](https://github.com/apple-oss-distributions/Libc/blob/main/posix1e/acl_file.c) и [entry iteration](https://github.com/apple-oss-distributions/Libc/blob/main/posix1e/acl_entry.c) задают семантику API. Darwin без cgo и неподдерживаемые платформы не дают такую authority. Linux helper проверяет owner/private mode и POSIX access ACL FD; это не Linux namespace launcher и не ресурсный допуск.

Версия 1 требует ровно десять canonical non-null полей: version, launch_nonce, plan_sha256, identity, started_at, read_at, bytes_sent, bytes_received, transport_quiescent, sdk_shutdown_outcome. Duplicate, unknown, missing, case aliases, malformed, trailing, oversize и неизвестные версии запрещены. Nonce и публичный fingerprint config/binary связывают запуск, но не аттестуют effective config/executable. Identity/start/ordinal берутся из независимо завершённого StartReceipt. Предыдущие показания сохраняются только как два counter high-water marks и binding/seen/invalid; invalid не сбрасывается. Итог обязан покрывать оба максимума и утверждать quiescence и успешный SDK shutdown.

Отдельный context-aware владелец проверяет артефакт после Done без terminal/member mutex и фиксирует копию, не меняя exit. FinalExact требует completed-start binding, чистый owned exit, успешные child/observer/scanners/parent closes и валидный отчёт. Остальные завершённые incarnation дают unavailable без значения счётчиков. StopReceipt.Ended optional: failed Start не добавляет нулевую или прежнюю incarnation. Неподтверждённое завершение сохраняет process/root; отменённая reduction после подтверждённого exit также сохраняет владельца для повтора и отличается от kernel StopUnconfirmed. Возвращаемые ended observations — глубокие копии.
