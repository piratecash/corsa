# Planned Linux Full and SDK members / Linux Full и SDK участники

`PrepareLinuxMemberGroup` copies and validates all original member tuples before effects. The existing Node plan consumer additionally checks the approved 240/4 address plan, distinct /16 source groups, roles and exact Full bootstrap set, then compiles its existing executor before `Setup`. This is the same executor and journal used by the functional stand.

Each member uses its original audited profile parent, anonymous namespace and helper channels. Successful Start is a fresh joint OS/RPC read followed by the original process CompletedStart binding; the earlier historical observation API is not converted into a receipt. Full uses the measured headless core entry, SDK uses normal SDK traffic. SDK listener stays disabled. Sample retains both real process provenance and ordinary RPC families. Stop joins the original target/helper/work owners, reduces its exact final report and disk peer endpoints, verifies isolation, then releases that incarnation’s channels/profile lease while its original group retains the same namespace/veth. Only the exact released predecessor can be consumed once by the next private planned fixture; the generic claimed bit is never reset. Restart creates a fresh launch binding in the same original namespace while reopening the same exact profile inode and verifying the same signed identity. Failed Start retains cleanup ownership and never creates an ended incarnation.

The guarded native entry is `TestLoadStandLinuxPlannedFullSDKTimelineNative`. It uses the existing two-Full/two-SDK DM, global-message and restart timeline and existing functional limits. Ordinary/short tests do not run it. Inputs are the existing native helper/SDK path+hash plus exact Full/NFT path+hash and the three numeric isolation probe endpoints. The host must supply the separately admitted network-none container, approved capabilities, audited tools and original profile mount. No automatic download, public fallback, kernel retry or foreign cleanup is performed.

These are implementation and functional-lifecycle checks, not T5 resource acceptance. Actual kernel/tool conformance, measurements and owner-approved thresholds remain separate. The fixed private packet bound remains unchanged. The original group supplies a sealed public full-membership FD/digest/count; the helper reads and closes it before target exec, streams final peer-state validation locally and returns only a bounded verdict/digest/count. Peer-state input is bounded by actual planned member count times the existing per-artifact byte bound, with streamed JSON/entry-count/address checks and the existing caller context. Receipt snapshots retain the existing caller count/byte bound but use ordered chunks on the same original work channel; no incomplete stream is published. Large fixture tests cover data beyond both old whole-file/frame boundaries. Actual tool/kernel conformance and resource/profile acceptance still require their separate runs.

Подготовка копирует исходный план; существующий исполнитель проверяет роли, bootstrap и разные /16 до сетевых эффектов. Start получает свежие факты через исходный helper, а не переносит историческое наблюдение. Stop подтверждает исходные joins, итоговый отчёт и peer-state, затем освобождает каналы и lease поколения; группа сохраняет исходные namespace/veth до своей конечной уборки. Только точный освобождённый predecessor допускает одно следующее поколение без сброса claimed. Перезапуск сохраняет namespace, адрес, исходный inode профиля и подписанную identity. Частичный запуск сохраняет обязанность уборки, без выдуманного завершённого поколения. Реальный Linux и тяжёлые измерения этим Source-пакетом не принимаются.


Runtime samples include the original process's Go heap after its resource reads. A nonserialized key from the original lifecycle owner groups shared-process Full services together and keeps external SDK/Linux processes separate; node role, identity and RSS do not establish that grouping. The executor checks the overflow-safe sum of each group's resource floors against its last runtime heap reading before journal completion. Missing runtime data, a foreign lifetime/owner or an impossible floor refuses the run. Before stopping a member it freshly samples all still-owned members in that process group, records which member triggered the check and still performs the original Stop after a sampling failure. Linux retains the existing OS/RPC provenance bracket. These coarse functional checks do not replace byte-balance, mixed-process/native conformance or resource acceptance.

Runtime-выборка содержит настоящий Go heap исходного процесса после чтения его ресурсов. Несериализуемый ключ исходного владельца объединяет Full-сервисы с общей heap и отделяет внешние SDK/Linux-процессы; роль, identity и RSS не служат основанием такого объединения. Перед завершением журнала исполнитель сравнивает сумму ресурсных полов группы с её последним чтением heap, проверяя переполнение. Отсутствие runtime, чужое поколение/владелец или невозможный пол отклоняют прогон. Перед остановкой заново читаются все ещё принадлежащие исполнителю участники той же process-группы с указанием инициатора; ошибка выборки не отменяет исходный Stop. Для Linux сохранён OS/RPC provenance bracket. Это грубая функциональная проверка, отдельно от баланса байтов, mixed/native conformance и ресурсной приёмки.
