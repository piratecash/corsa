# Planned Linux Full and SDK members / Linux Full и SDK участники

`PrepareLinuxMemberGroup` copies and validates all original member tuples before effects. The existing Node plan consumer additionally checks the approved 240/4 address plan, distinct /16 source groups, roles and exact Full bootstrap set, then compiles its existing executor before `Setup`. This is the same executor and journal used by the functional stand.

Each member uses its original audited profile parent, anonymous namespace and helper channels. Successful Start is a fresh joint OS/RPC read followed by the original process CompletedStart binding; the earlier historical observation API is not converted into a receipt. Full uses the measured headless core entry, SDK uses normal SDK traffic. SDK listener stays disabled. Sample retains both real process provenance and ordinary RPC families. Stop joins the original target/helper/work owners, reduces its exact final report and disk peer endpoints, verifies isolation, then releases that incarnation’s channels/profile lease while its original group retains the same namespace/veth. Only the exact released predecessor can be consumed once by the next private planned fixture; the generic claimed bit is never reset. Restart creates a fresh launch binding in the same original namespace while reopening the same exact profile inode and verifying the same signed identity. Failed Start retains cleanup ownership and never creates an ended incarnation.

The guarded native entry is `TestLoadStandLinuxPlannedFullSDKTimelineNative`. It uses the existing two-Full/two-SDK DM, global-message and restart timeline and existing functional limits. Ordinary/short tests do not run it. Inputs are the existing native helper/SDK path+hash plus exact Full/NFT path+hash and the three numeric isolation probe endpoints. The host must supply the separately admitted network-none container, approved capabilities, audited tools and original profile mount. No automatic download, public fallback, kernel retry or foreign cleanup is performed.

These are implementation and functional-lifecycle checks, not T5 resource acceptance. Actual kernel/tool conformance, measurements and owner-approved thresholds remain separate. The fixed private packet bound remains unchanged. The original group supplies a sealed public full-membership FD/digest/count; the helper reads and closes it before target exec, streams final peer-state validation locally and returns only a bounded verdict/digest/count. Peer-state input is bounded by actual planned member count times the existing per-artifact byte bound, with streamed JSON/entry-count/address checks and the existing caller context. Receipt snapshots retain the existing caller count/byte bound but use ordered chunks on the same original work channel; no incomplete stream is published. Large fixture tests cover data beyond both old whole-file/frame boundaries. Actual tool/kernel conformance and resource/profile acceptance still require their separate runs.

Подготовка копирует исходный план; существующий исполнитель проверяет роли, bootstrap и разные /16 до сетевых эффектов. Start получает свежие факты через исходный helper, а не переносит историческое наблюдение. Stop подтверждает исходные joins, итоговый отчёт и peer-state, затем освобождает каналы и lease поколения; группа сохраняет исходные namespace/veth до своей конечной уборки. Только точный освобождённый predecessor допускает одно следующее поколение без сброса claimed. Перезапуск сохраняет namespace, адрес, исходный inode профиля и подписанную identity. Частичный запуск сохраняет обязанность уборки, без выдуманного завершённого поколения. Реальный Linux и тяжёлые измерения этим Source-пакетом не принимаются.


Runtime samples include the original process's Go heap after its resource reads. A nonserialized key from the original lifecycle owner groups shared-process Full services together and keeps external SDK/Linux processes separate; node role, identity and RSS do not establish that grouping. The executor checks the overflow-safe sum of each group's resource floors against its last runtime heap reading before journal completion. Missing runtime data, a foreign lifetime/owner or an impossible floor refuses the run. Before stopping a member it freshly samples all still-owned members in that process group, records which member triggered the check and still performs the original Stop after a sampling failure. Linux retains the existing OS/RPC provenance bracket. These coarse functional checks do not replace mixed-process/native conformance or resource acceptance. Byte-balance scope is described below.

Runtime-выборка содержит настоящий Go heap исходного процесса после чтения его ресурсов. Несериализуемый ключ исходного владельца объединяет Full-сервисы с общей heap и отделяет внешние SDK/Linux-процессы; роль, identity и RSS не служат основанием такого объединения. Перед завершением журнала исполнитель сравнивает сумму ресурсных полов группы с её последним чтением heap, проверяя переполнение. Отсутствие runtime, чужое поколение/владелец или невозможный пол отклоняют прогон. Перед остановкой заново читаются все ещё принадлежащие исполнителю участники той же process-группы с указанием инициатора; ошибка выборки не отменяет исходный Stop. Для Linux сохранён OS/RPC provenance bracket. Это грубая функциональная проверка, отдельно от mixed/native conformance и ресурсной приёмки. Границы баланса байтов описаны ниже.


Byte balance is now composed into the same executor and journal (executor version 3). Only complete periodic network sweeps are edges: the first is the fixed anchor, each later complete sweep is checked against it with the existing unchanged default tolerance and the whole original stopped-life history. Traffic uses the original transport counters, real service StartedAt/ReadAt and actual collector clock brackets; the journal metadata clock may jump independently of the monotonic schedule. Runtime process groups do not partition the byte network. Original Ended prefixes are frozen as scalar copies after each Stop, checked before a restart can replace its successful receipt, and rechecked during cleanup. Invalid source/history/counter ranges fail the run; they are not harmless undefined balance.

Results distinguish judged_no_defect, defect and undefined. Short genuine traffic may be undefined because zero volume or the unchanged provisional in-flight/read-skew allowance is too large; a functional lifecycle can still complete with this explicit unjudged result and AcceptanceEligible=false. Undefined is never reported as judged PASS, and its infinite zero-volume share is represented as absent, not a fabricated zero. A partial process-group PreStopOf read is not a network edge. The already scheduled final periodic sweep is reused without new sampling calls. Reconciliation after cleanup covers exactly the same genuine pair; final drain/shutdown traffic and an all-stopped terminal edge remain terminal_tail_unjudged. No final-as-live nodes, synthetic counters, zeroed missing peers or enlarged tolerance extend that coverage. Loopback closed membership is a declared controlled-fixture assumption; plan compilation alone does not prove socket isolation, and actual Linux boundary/resource conformance remains separate. The Source-invalid journal controls are not the judged arithmetic byte-balance RED; a sufficiently powerful genuine C1 load window is still required for that control.

Баланс байтов включён в тот же executor и journal (версия исполнителя 3). Границами служат только полные periodic network sweeps: первая остаётся anchor, каждая следующая сверяется с ней неизменённым checker и default tolerance, с полной исходной историей остановленных поколений. Используются настоящие transport counters, StartedAt/ReadAt и реальные границы чтения; скачки journal clock не меняют монотонное расписание. Исходная Ended history копируется после каждого Stop до замены receipt при restart и снова проверяется при cleanup. Повреждённый источник или переполнение отклоняют прогон.

Undefined не означает PASS: короткого настоящего трафика может не хватить при прежнем in-flight allowance. Такой functional lifecycle может завершиться только с явным unjudged и AcceptanceEligible=false. Бесконечная доля при нулевом объёме сериализуется как отсутствующее значение, не как ноль. Частичный PreStopOf не становится сетевой границей. Используется уже запланированная последняя periodic sweep; новых чтений нет. Завершающая сверка не расширяет её интервал: drain/shutdown и all-stopped terminal остаются terminal_tail_unjudged. Подстановка отсутствующих узлов/нулей и изменение tolerance запрещены. Настоящий C1-объём для judged arithmetic RED, Linux isolation и ресурсная приёмка остаются отдельными.
