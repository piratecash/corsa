# What's New in v2.1.67

## Message Reactions

Corsa now supports one-to-one, offline-first message reactions. Long press a message, or open its menu, to pick a quick reaction or choose another emoji from the full picker. Tapping the same reaction again removes it. Reaction chips under the bubble show the emoji, the count, and which reaction is yours.

Reactions travel as their own control message over the datagram plane, sealed to the pair and padded to a fixed size. Relays see an indistinguishable frame rather than a visible "someone reacted" event. Reactions can arrive before the message they refer to and appear once that message lands.

Both sides converge without needing to be online at the same time. Lost frames, duplicates, reordering, and long offline periods all settle to the latest decision, including removals. Older peers are not sent reaction frames they cannot understand; the UI keeps the reaction local and says why until the peer can receive it.

Deleting a message also deletes the reactions attached to it, and a later replay from the peer cannot bring them back.

## Clear a Chat on Both Sides

Conversation clearing is now a single request about the thread, not a list of message deletes. That makes it safe for peers whose local histories differ: the request names the conversation, outlives the rows it came from, and can be re-issued to repair a thread an older build split in half.

The receiving side treats a wipe as mutual forgetting and does not check message authorship. This fixes the old half-cleared state where each side could keep the other person's messages. The request is not written off after one application, and the system no longer records deletion facts or deletion timestamps in persistent logs.

Attachment cleanup is tied to the deleted messages as work owed until the files are actually gone, surviving failed unlink attempts, unflushed directories, and restarts. Shared downloads are removed only when the last message that references the file is gone.

## View Images Inside the App

Image attachments can now be opened in an in-app viewer over the whole window, including over the console. The strip contains every image in the current conversation in message order; images that are still downloading keep their place and show a loading state until the file arrives.

The viewer decodes full-resolution images into its own byte-bounded cache, with thumbnail previews used while decoding. This keeps large photos useful without letting a few high-resolution images exhaust memory, especially on Android.

Zoom supports 100%, 200%, and 400% buttons, Ctrl+wheel, pinch gestures, and double-tap 100%/200% toggling. A magnified image can be dragged with one finger; navigation to the next image happens only when the image edge has reached the viewport.

You can now delete this node's local copy of a received file without deleting the message. The message remains in the chat, loses its local preview, and offers to download the attachment from the peer again. Outgoing image files are not locally removed this way because this node's copy is the transmit source recipients download from.

Saving an image writes to the platform downloads folder without overwriting existing files. Android attach/save integration was repaired by packaging the picker classes correctly and using an activity mode that can receive picker results.

## `corsa:` Links Reach the Running App

Deep links now work as a first-class cross-platform contract. The `corsa:` scheme is registered in the places each platform actually reads: macOS bundle metadata, Linux desktop/MIME registration, Android VIEW/BROWSABLE intent filters, and Windows per-user registration generated by Gio's linker flag.

Links are parsed before being acted on. A bare 40-hex payload is treated as a contact address, `corsa:<kind>/<payload>` is the extensible shape for newer link types, and unsupported kinds are reported separately from malformed links.

Only one desktop instance owns a data directory and port. If a clicked link starts a second app process, that process hands the link to the already-running owner through a local socket and exits without opening the shared state or starting a second node. Terminal-launched second instances remain intentional.

The local socket is claimed before the database opens and closed at shutdown start, so a link is not acknowledged by an instance that can no longer act on it. Android now reads and consumes the launch intent itself to avoid a cold-start race with Gio's event iterator.

`docs/deeplinks.md` documents the URI family, routing table, platform registration requirements, and manual verification steps.

Regression coverage was added across reaction state convergence, sealed reaction control payloads, conversation wipe delivery and attachment cleanup, file-transfer local-copy deletion, image viewer cache/input behavior, platform downloads resolution, deeplink parsing/routing/local handoff, and platform registration files.

# Что нового в v2.1.67

## Реакции на сообщения

Corsa теперь поддерживает реакции на сообщения в личных чатах, включая работу офлайн. Долгое нажатие на сообщение или меню сообщения открывает быстрые реакции и полный выбор эмодзи. Повторное нажатие на свою реакцию снимает её. Метки под сообщением показывают эмодзи, количество реакций и какая реакция принадлежит вам.

Реакции передаются отдельным управляющим сообщением через датаграммный слой, шифруются для пары участников и дополняются до фиксированного размера. Ретранслятор видит не событие "кто-то поставил реакцию", а неотличимый служебный кадр. Реакция может прийти раньше сообщения, к которому относится, и появится, когда само сообщение окажется на месте.

Обе стороны сходятся к одному состоянию без необходимости одновременно быть онлайн. Потерянные кадры, дубликаты, изменение порядка доставки и долгий офлайн-период всё равно приводят к последнему принятому решению, включая снятие реакции. Старым пирам не отправляются кадры реакций, которые они не умеют читать; интерфейс оставляет реакцию локальной и объясняет почему, пока пир не сможет её принять.

Удаление сообщения также удаляет реакции к нему, и поздний повтор от пира не поднимает их обратно.

## Очистка чата на обеих сторонах

Очистка чата теперь является одним запросом о переписке, а не списком удалений отдельных сообщений. Поэтому она безопасна, когда локальные истории у пиров отличаются: запрос называет переписку, живёт дольше строк, из которых появился, и может быть отправлен повторно, чтобы починить чат, который старая сборка разделила пополам.

Принимающая сторона трактует wipe как взаимное забывание и не проверяет авторство сообщений. Это исправляет старое наполовину очищенное состояние, где каждая сторона могла оставить у себя сообщения другого человека. Запрос не списывается после одного применения, а система больше не пишет факты удаления или время удаления в постоянные логи.

Очистка вложений привязана к удалённым сообщениям как отложенная работа, пока файлы реально не исчезнут: она переживает неудачный `unlink`, несброшенные директории и перезапуски. Общие скачанные файлы удаляются только когда исчезло последнее сообщение, которое ссылается на этот файл.

## Просмотр изображений внутри приложения

Вложения-изображения теперь открываются во встроенном просмотрщике поверх всего окна, включая консоль. Лента содержит все изображения текущей переписки в порядке сообщений; изображения, которые ещё скачиваются, сохраняют своё место и показывают состояние загрузки, пока файл не появится.

Просмотрщик декодирует изображения в полном разрешении в собственный кэш с лимитом по байтам, а во время декодирования показывает миниатюру. Это позволяет удобно смотреть большие фото и не даёт нескольким изображениям высокого разрешения съесть память, особенно на Android.

Масштабирование поддерживает кнопки 100%, 200% и 400%, Ctrl+wheel, жест pinch и двойное нажатие для переключения 100%/200%. Увеличенное изображение можно двигать одним пальцем; переход к следующему изображению происходит только когда край картинки дошёл до области просмотра.

Теперь можно удалить локальную копию полученного файла на этой ноде, не удаляя сообщение. Сообщение остаётся в чате, теряет локальный предпросмотр и предлагает снова скачать вложение у пира. Исходящие изображения так локально не удаляются, потому что копия этой ноды является источником передачи, откуда получатели скачивают файл.

Сохранение пишет изображение в системную папку загрузок без перезаписи существующих файлов. Android-интеграция прикрепления и сохранения исправлена: классы выбора файлов теперь корректно попадают в пакет, а режим activity позволяет получить результат выбора.

## Ссылки `corsa:` доходят до уже запущенного приложения

Deep links теперь оформлены как кросс-платформенный контракт. Схема `corsa:` регистрируется там, где конкретная платформа реально её читает: metadata bundle на macOS, desktop/MIME registration на Linux, VIEW/BROWSABLE intent filters на Android и пользовательская регистрация на Windows через Gio linker flag.

Ссылки сначала разбираются и классифицируются, и только потом исполняются. Bare 40-hex payload считается адресом контакта, `corsa:<kind>/<payload>` становится расширяемой формой для новых типов ссылок, а неподдерживаемый kind отличается от некорректной ссылки.

Только один экземпляр desktop-приложения владеет каталогом данных и портом. Если клик по ссылке запускает второй процесс, он передаёт ссылку уже работающему владельцу через локальный socket и выходит, не открывая общее состояние и не поднимая вторую ноду. Вторые экземпляры из terminal остаются намеренным сценарием.

Локальный socket занимается до открытия database и закрывается в начале shutdown, поэтому link не подтверждается экземпляром, который уже не сможет его обработать. Android теперь сам читает и consumes launch intent, чтобы убрать cold-start race с Gio event iterator.

`docs/deeplinks.md` описывает семейство URI, таблицу маршрутизации, требования к регистрации на платформах и ручные проверки.

Регрессионные тесты добавлены для сходимости реакций, зашифрованных управляющих payloads реакций, доставки conversation wipe и очистки вложений, удаления локальной копии file transfer, поведения кэша и ввода image viewer, определения системной папки загрузок, разбора/routing/local handoff deeplinks и файлов platform registration.
