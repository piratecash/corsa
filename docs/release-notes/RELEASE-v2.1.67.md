# What's New in v2.1.67

## Message Reactions

Corsa now supports one-to-one, offline-first message reactions. Long press a message, or open its menu, to pick a quick reaction or choose another emoji from the full picker. Tapping the same reaction again removes it. Reaction chips under the bubble show the emoji, the count, and which reaction is yours.

Reactions travel as their own control message over the datagram plane, sealed to the pair and padded to a fixed size. Relays see an indistinguishable frame rather than a visible "someone reacted" event. Reactions can arrive before the message they refer to and appear once that message lands.

Both sides converge without needing to be online at the same time. Lost frames, duplicates, reordering, and long offline periods all settle to the latest decision, including removals. Older peers are not sent reaction frames they cannot understand; the UI keeps the reaction local and says why until the peer can receive it.

Deleting a message also deletes the reactions attached to it, and a later replay from the peer cannot bring them back.

## Clear a Chat on Both Sides

Conversation clearing is now a single request about the thread, not a list of message deletes. That makes it safe for peers whose local histories differ: the request names the conversation, outlives the rows it came from, and can be re-issued to repair a thread an older build split in half.

The receiving side treats a wipe as mutual forgetting and does not check message authorship. This fixes the old half-cleared state where each side could keep the other person's messages. The request is not written off after one application, and the system no longer records deletion facts or deletion timestamps in persistent logs.

Attachment cleanup is tied to the deleted messages as work owed until the files are actually gone, surviving failed unlink attempts, unflushed directories, and restarts. Shared downloads are removed only when the last message that references the file is gone.

## View Images Inside the App

Image attachments can now be opened in an in-app viewer over the whole window, including over the console. The strip contains every image in the current conversation in message order; images that are still downloading keep their place and show a loading state until the file arrives.

The viewer decodes full-resolution images into its own byte-bounded cache, with thumbnail previews used while decoding. This keeps large photos useful without letting a few high-resolution images exhaust memory, especially on Android.

Zoom supports 100%, 200%, and 400% buttons, Ctrl+wheel, pinch gestures, and double-tap 100%/200% toggling. A magnified image can be dragged with one finger; navigation to the next image happens only when the image edge has reached the viewport.

You can now delete this node's local copy of a received file without deleting the message. The message remains in the chat, loses its local preview, and offers to download the attachment from the peer again. Outgoing image files are not locally removed this way because this node's copy is the transmit source recipients download from.

Saving an image writes to the platform downloads folder without overwriting existing files. Android attach/save integration was repaired by packaging the picker classes correctly and using an activity mode that can receive picker results.

## `corsa:` Links Reach the Running App

Deep links now work as a first-class cross-platform contract. The `corsa:` scheme is registered in the places each platform actually reads: macOS bundle metadata, Linux desktop/MIME registration, Android VIEW/BROWSABLE intent filters, and Windows per-user registration generated by Gio's linker flag.

Links are parsed before being acted on. A bare 40-hex payload is treated as a contact address, `corsa:<kind>/<payload>` is the extensible shape for newer link types, and unsupported kinds are reported separately from malformed links.

Only one desktop instance owns a data directory and port. If a clicked link starts a second app process, that process hands the link to the already-running owner through a local socket and exits without opening the shared state or starting a second node. Terminal-launched second instances remain intentional.

The local socket is claimed before the database opens and closed at shutdown start, so a link is not acknowledged by an instance that can no longer act on it. Android now reads and consumes the launch intent itself to avoid a cold-start race with Gio's event iterator.

`docs/deeplinks.md` documents the URI family, routing table, platform registration requirements, and manual verification steps.

Regression coverage was added across reaction state convergence, sealed reaction control payloads, conversation wipe delivery and attachment cleanup, file-transfer local-copy deletion, image viewer cache/input behavior, platform downloads resolution, deeplink parsing/routing/local handoff, and platform registration files.

# Что нового в v2.1.67

## Reactions на сообщения

Corsa теперь поддерживает one-to-one, offline-first reactions на сообщения. Long press на message, или меню сообщения, открывает быстрые reactions и полный emoji picker. Повторный tap по своей reaction снимает её. Chips под bubble показывают emoji, количество и какая reaction принадлежит вам.

Reactions ходят отдельным control message через datagram plane, sealed to the pair и padded до fixed size. Relay видит не "кто-то reacted", а неотличимый frame. Reaction может прийти раньше сообщения, к которому относится, и появится, когда само сообщение окажется на месте.

Обе стороны сходятся без необходимости быть online одновременно. Lost frames, duplicates, reordering и долгий offline period всё равно приводят к последнему принятому решению, включая removal. Старым peers не отправляются reaction frames, которые они не умеют читать; UI оставляет reaction локальной и объясняет это, пока peer не сможет её принять.

Удаление сообщения также удаляет reactions к нему, и поздний replay от peer не поднимает их обратно.

## Очистка чата на обеих сторонах

Conversation clear теперь является одним request про thread, а не списком message deletes. Поэтому он безопасен, когда истории у peers отличаются: request называет conversation, живёт дольше строк, из которых появился, и может быть отправлен повторно, чтобы починить thread, который старый build разделил пополам.

Receiving side трактует wipe как mutual forgetting и не проверяет authorship сообщений. Это исправляет старое half-cleared состояние, где каждая сторона могла оставить у себя сообщения другого человека. Request не списывается после одного применения, а система больше не пишет deletion facts или deletion timestamps в persistent logs.

Attachment cleanup привязан к удалённым сообщениям как work owed, пока файлы реально не исчезнут: это переживает failed unlink, unflushed directories и restarts. Shared downloads удаляются только когда исчезло последнее сообщение, которое ссылается на этот file.

## Просмотр изображений внутри приложения

Image attachments теперь открываются во встроенном viewer поверх всего окна, включая console. Strip содержит все images текущего conversation в message order; изображения, которые ещё скачиваются, сохраняют своё место и показывают loading state, пока file не появится.

Viewer декодирует full-resolution images в собственный byte-bounded cache, а пока идёт decode показывает thumbnail preview. Это позволяет удобно смотреть большие фото и не даёт нескольким high-resolution images съесть память, особенно на Android.

Zoom поддерживает кнопки 100%, 200% и 400%, Ctrl+wheel, pinch gestures и double-tap toggle 100%/200%. Magnified image можно двигать одним пальцем; переход к следующему изображению происходит только когда край картинки дошёл до viewport.

Теперь можно удалить локальную копию received file на этой node, не удаляя сообщение. Message остаётся в chat, теряет local preview и предлагает снова скачать attachment у peer. Outgoing image files так локально не удаляются, потому что копия этой node является transmit source, откуда recipients скачивают файл.

Save пишет image в platform downloads folder без overwrite существующих файлов. Android attach/save integration исправлена: picker classes теперь корректно попадают в package, а activity mode позволяет получить picker result.

## `corsa:` links доходят до запущенного приложения

Deep links теперь оформлены как cross-platform contract. Scheme `corsa:` регистрируется там, где конкретная платформа реально его читает: macOS bundle metadata, Linux desktop/MIME registration, Android VIEW/BROWSABLE intent filters и Windows per-user registration через Gio linker flag.

Links сначала парсятся и называются, и только потом исполняются. Bare 40-hex payload считается contact address, `corsa:<kind>/<payload>` становится расширяемой формой для новых типов links, а unsupported kind отличается от malformed link.

Только один desktop instance владеет data directory и port. Если clicked link запускает второй процесс, он передаёт link уже работающему owner через local socket и выходит, не открывая shared state и не поднимая вторую node. Вторые instances из terminal остаются намеренным сценарием.

Local socket занимается до открытия database и закрывается в начале shutdown, поэтому link не acknowledge'ится instance'ом, который уже не сможет его обработать. Android теперь сам читает и consumes launch intent, чтобы убрать cold-start race с Gio event iterator.

`docs/deeplinks.md` описывает URI family, routing table, platform registration requirements и manual verification steps.

Regression coverage добавлена для reaction state convergence, sealed reaction control payloads, conversation wipe delivery и attachment cleanup, file-transfer local-copy deletion, image viewer cache/input behavior, platform downloads resolution, deeplink parsing/routing/local handoff и platform registration files.
