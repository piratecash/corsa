# Закрытые направленные роли FIND_NODE

Закрытый путь D1 теперь разрешает пересылку по неизменяемой **локальной** роли, выбранной до создания Service/Ready. Обычные фабрики Core/App остаются Off. Новых env, RPC, config-переключателей или публичного включения нет.

| Локальная роль | Тип узла | Собственная TLS-декларация | Обработка запроса |
| --- | --- | --- | --- |
| Off | Существующие типы | Роль не добавляет F1/R | Закрытый FIND_NODE недоступен |
| Target | Full или Client | Только F1 | Ответ о себе; пересылка запрещена |
| Responder | Только Full | F1 + R | Ответ о себе либо исходный путь пересылки |

Одно значение конструктора связывает первый Service literal, Ready и TLS-декларацию. Неизвестные роли и сочетание Responder/Client отклоняются. Проверка чужой цели идёт после исходных proof/F1/frame-проверок, до полного обхода реестра и intake. Проверки ConnID, времени жизни сессии, fairness, квот и подписанного ответа сохранены. Чужой R не даёт локальных полномочий; клиент только с F1 может принять пересланный запрос и ответить о себе. Симметричное пересечение R для этого закрытого Target-пути не требуется.

Tagged-диагностика явно выбирает частную роль. Это закрытая инженерная реализация, а не публичный выбор роли. Направленная трактовка публичного wire-контракта §2 остаётся до G2; решение владельца не подразумевается.
