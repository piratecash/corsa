# Завершение настройки собственной namespace участника

Закрытый Linux-стенд loadstand теперь выполняет отдельную завершающую операцию настройки после всех carrier-UP bridge/veth и перед исходной проверкой участника только для чтения. Операция привязана к исходным identity namespace, nonce плана, имени peer и индексу, полученному при его настройке; уже занятые или заменённые ресурсы отвергаются. Используется прежний строгий отбор всего дампа multicast-маршрутов, точное удаление собственного маршрута и проверка результата. Адреса не назначаются, интерфейсы повторно не поднимаются, проверка только для чтения не превращается в очистку. Финальная очистка хоста и строгие проверки маршрутов/адресов сохранены. Поведение обычного corsad и публичная активация не меняются.

Проверенный срез — база `c8e77b8f6723cf928e2d4465c9a4c17e535846e6` и четыре файла из манифеста [переносимого пакета](evidence/d1-o1a-member-finalization-2026-11-20/README.md); это отдельный срез от исторического application ELF O1a `4fcc`. На Go 1.27.4 собран test ELF Linux arm64/CGO0; **14 выбранных тестов верхнего уровня и 74 дочерних случая прошли** в офлайн-контейнере без capabilities: 1 CPU, 512000000 байт, 64 PID, без swap. Линтер golangci-lint v2.14.0 для Linux не нашёл замечаний. Для этой правки стенда повторный полный продуктовый набор не требовался. Пакет сохраняет точные исходники, контроллеры, полные RAW, хеши входов и независимые проверки.

Отдельная реальная диагностика carrier завершилась **NOT_REPRODUCED**: один точно принадлежащий стенду multicast-маршрут был проверен и удалён, остаток дампа подтверждён чистым, но позднее создание маршрута из исходного Go-падения не воспроизведено. Правка устраняет обоснованный пробел порядка настройки, не доказывая причину прежнего отказа. Регрессия на имитации явно добавляет поздний маршрут и проверяет очистку перед неизменённым строгим аудитом только для чтения. Прежние отказы сохранены. Исходный Go/O1a и D1 остаются **NOT PASS**; допуск выпуска, G2 или публичная активация этим не предоставляются.
