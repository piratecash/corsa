# Одноразовая диагностика первой причины observer

Закрытая диагностическая версия сохраняет первый код семейства ошибки в исходных местах отказа route-wire observer. Решения об отказе сохранены; произвольные ошибки, payload и ключи не выводятся. Инструментирование меняет хеш измеряемого Core, поэтому эта версия одноразовая: по ней нельзя принимать baseline-скорости или лимит 512 MB. [Подготовка доказательств](evidence/d1-observer-first-failure-2026-11-20/README.md) сохраняет исходники и полную последовательность попыток.

Первый host QA упал, потому что новый тест передавал тип frame, который observer не выбирает. После замены только тестового стимула на исходную константу протокола прошли 36 внешних тестов и 147 подтестов. Свежее чтение через исходный Source API подтвердило 640 measured-файлов (`9fb7…`) и 708 stand-файлов (`9827…`); четыре статических Linux arm64 артефакта собраны и проверены без запуска. PID1 и capexec пересобраны с новыми хешами артефактов. Неизменный exporter использован повторно по точному совпадению его скомпилированных зависимостей.

Единственный запуск VM `9b75…` упал раньше целевой диагностики observer. Исходный setup отверг `ff00::/8` в `plannedInNamespace:guard4`, `configure=true`, ещё до создания журнала или полезного окна; Go завершился с FAIL на 0,13 секунды. Первое семейство ошибки observer поэтому не получено; внутренние причины прежних 30- и 480-секундных отказов остаются UNKNOWN. VM/worker штатно остановлены, все гостевые дети завершены и собраны, очистка выполнена после трёх независимых stopped-only проверок. Go FAIL сохранён; физическое завершение XPC остаётся UNKNOWN.

Отдельное исправление фикстуры передаёт последний фактический полный AF_INET6 dump строгого reconciler в неизменную исходную проверку маршрутов вместе со снимком AF_INET. Второй независимый IPv6 dump между очисткой и проверкой устранён. Владение, проверка всего набора полей маршрута, точное удаление/readback, post-carrier finalization и последующие свежие read-only/preclaim проверки сохранены; повторов, sleep и исключения для `ff00` нет. Изменены три исходных файла фикстуры и добавлен один чистый тест; Core/приложения не изменены. На точной изолированной копии исходников в прежнем ограниченном контейнере прошли 17 внешних Linux-тестов и 84 подтеста; targeted Linux lint сообщил ноль замечаний. Это подтверждает детерминированную регрессию снимка/отказов, а не точный момент события ядра в сохранённом отказе или успех исправленной VM. Исходные periodic/reconnect скорости, приёмка D1 и публичная активация не подтверждены.
