## Предмет и полезная работа

Настоящий `./cmd/corsa-node`, keeper и его дочерний sampler входят в **один service-контейнер/cgroup**. Прежние 128 MiB observer к нему не добавляются. Драйвер нагрузки остаётся отдельным. Исходник — commit `8afa7f5b365a56d55f116c8a0dfb0ac581c79000`; закоммиченные Python/Markdown-правки aa86db12 не меняют Go/modules/build recipe. Это текущий кандидат, не финальный релиз D1.

Повторно используется [tracked c2driver](../../internal/testutil/loadstand/c2driver/main.go), фиксированный `C2B32-v1`: свежий 0 → 32 доказанные TLSv2-сессии → закрыть/join 16 → 16 выживших → 16 новых identity → 32 → закрыть/join все → свежий active 0. Всего 48 identity, 224 завершённые полезные `ping/get_peers/ping` последовательности, 672 основные request/reply пары (1344 основных application frames). Это не total wire/RPC: дополнительные bounded control frames учитываются отдельно. Сохраняются четыре phase receipts и доступные per-peer counters. 224 завершения подтверждаются успешным control-flow точного Source/артефакта; это не сумма terminal RAW counters всех 48 peers. Первые 16 после закрытия больше не выводятся: их последнее видимое значение 1, фактическое по успешному циклу 5. Формат драйвера не расширяется.

Драйвер запускается без argv с CORSA_C2B32_RUN=1; CORSA_C2A_RUN отсутствует, включая present-empty. Closed stdin activation содержит ровно ready/profile/nonce/approval_sha256/cli_sha256/server_identity/server_started_at/work_millis; work_millis=80000 разрешён только при достаточном остатке общего срока на work и завершение. Эти поля сами не доказывают допуск; secrets туда не попадают.

Прежние ограничения драйвера: четыре 5-секундных hold, 2 с/операция, 80 с work, 2048 application frames/8 MiB, максимум 128 RPC/8 MiB. Выход драйвера сам по себе не доказывает 0: обязателен его исходный свежий authenticated Node incarnation/status/instantaneous loopback-active oracle. Прежнее source-bound ограничение RAW финального 0 описывается честно; отдельное несохранённое тело ответа не выдумывается.

Нет F1/FindNode advertisement/активации, S6 Capture, application-message/SQLite/Desktop, 512-peer population, overload или длительного роста state. K9/K10/K12 opt-in выключены. Это полезная ограниченная TLS/churn/RPC работа с новым учётом, не полная 512 МБ/D1-приёмка и не стоимость одной сессии по старым числам.

## Окно измерения и результат

До запуска daemon удерживаются проверенные read-only cgroup FD, его identity, actual memory.max/cpu.max/pids.max/no-swap, membership и начальные memory.peak/events. У свежей cgroup начальные oom/oom_kill/oom_group_kill обязаны быть 0: ранний OOM не скрывается baseline. Peak не сбрасывается. Keeper/daemon/sampler связываются PID/birth/executable и actual cgroup; CURRENT/FOR_CHILDREN FD удерживаются и проверяются внутри service-группы до полезной работы и в bookends. Нет zero-offset исключения или перевода часов.

Предложена cadence 500 мс на интервале от sampler-ready до запуска daemon и до daemon reap, с учётом обоих краевых gaps; фактический gap >2 с или пропуск RAW означает неполное покрытие. Остановка sampler и дальнейший keeper-seal после daemon reap не являются запланированными 500-мс samples: непрерывный kernel peak/events охватывает отдельное окно creation→seal. Упорядоченный NDJSON/read brackets, CPU, cgroup current/peak/events и sampled RSS/HWM/PSS публикуются отдельно. Полный SHA daemon проверяется до полезной работы и после; внутри sampling — удерживаемая executable identity. Не использовать repeated full-ELF hashes из LinuxProcessSampler.Sample как высокочастотный collector.

После normal exit 0/reap daemon + sampler keeper ещё жив: читает final kernel peak/current/events и actual membership. Это не atomic snapshot: собственный read-bracket ограничивает момент чтения peak; чтения events до и после peak обязаны оставаться 0, current публикуется отдельно со своим bracket. Конец выбранного окна — это ограниченное наблюдение peak, а не выдуманный общий точный instant. Остаться может только keeper; неизвестные descendants срывают seal. Окно peak — создание свежей cgroup → этот final read, включая весь lifetime daemon и sampler. **Keeper-only exit-tail peak/OOM после финального чтения UNKNOWN.** Hard limits продолжают действовать до exit, но наблюдённое не называется full-group-lifetime peak. Обязательны normal exit 0 и reap daemon/driver/sampler/keeper, RAW/EOF, очистка own containers/volumes и свежие absence queries. Принудительное удаление может подтвердить очистку после отказа, но не заменяет успешное выполнение работы.

Sampled RSS/HWM/PSS — дополнительные метрики атрибуции; недоступные значения остаются UNKNOWN. Обязательные peak/events, identity, работа и покрытие не могут отсутствовать.

Scoped-успех требует точной полезной работы в deadline, полного покрытия, стабильных identity/cgroup, OOM events 0 до seal, действительного kernel peak ≤512000000 и normal owned exits/cleanup. Маленький peak из-за недовыполнения работы не PASS. Missing/unreadable/reset counter, смена identity/clock, потеря final RAW или UNKNOWN closure — INCOMPLETE/UNKNOWN; наблюдённый functional FAIL/OOM — FAIL. Факты не скрываются за общей меткой.

Основная метрика — **charged cgroup peak в объявленном окне**, со всеми тремя сервисными ролями. Это не сумма RSS, отдельная цена corsad/sampler, physical shared-page upper bound или безопасность соседних сервисов. Неатрибутированный shared tmpfs/page charge остаётся UNKNOWN, ничего не вычитается. Сравнение — только при одинаковых инструментализации/платформе/нагрузке; старые цифры не становятся baseline новой layout.
