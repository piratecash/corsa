# Узкая диагностика preparer SG32: проект допуска

Исторический проект: владелец выбрал полную попытку SG32; этот preparer-only пакет не активировался и не запускался. Его привязка Host5221 предшествует последующему исправлению режима manifest и не является актуальным допуском исполнения.

Статус: исходники проверены независимым ревью и успешным pure-набором; ресурсный пакет требует отдельного допуска владельца. Документ не разрешает исполнение. Два прежних допуска SG32 израсходованы; исходные журналы и отказы сохраняются отдельно.

Цель — установить конкретную отказавшую операцию preparer с числовым errno и ограниченными метаданными. Точная причина PermissionError второй попытки пока UNKNOWN. Диагностический helper уже прошёл 28 методов/128 вложенных pure-сценариев; эти проверки не воспроизводят Linux DAC с UID0/onlyCAP_CHOWN.

Новый отдельный контроллер использует профиль SG32-PREPARER-ONLY-v1. Он должен создать и запустить ровно один preparer; после PREPARED, ERROR, неправильного ответа или таймаута перейти к очистке. Corsad, c2driver, keeper и sampler не создаются и не запускаются. Бинарники corsad/c2driver копируются как непрозрачные проверенные входные файлы исходного сценария. Требуется независимая граница разрешённых Docker-команд, включая интерактивный start; вызов полного sg32_host.run запрещён. Старый SG32-v1 bootstrap/контроллер должен отвергать новый профиль.

Ресурсы: один preparer, 0,25 CPU / 134217728 байт / 32 PID; MemorySwap=Memory, UID:GID0:0, CapDropALL и только CHOWN/CAP_CHOWN, no-new-privileges, rootfs read-only, network none, без host mounts/privileged и piratecashd. Три свежих собственных volume; секретный tmpfs <=1MiB. Существующий точный Linux arm64 image910cfcaf… с pull=never; без сборки, загрузок и скачиваний. Владельцы/права/порядок копирования не исправляются: это диагностическая попытка, не проверка предполагаемого решения.

Весь этап — до180с с подготовкой и до30с очистки; preparer до20с внутри этого окна. Сроки программные; гарантированного срока остановки зависшего FS/syscall нет. Host hard CPU/RAM/PID limits, host no-swap и жёсткая дисковая квота не обеспечиваются. Canonical heavy-lock/PGID/локальный Docker endpoint сохраняются. Перед запуском >=10GiB свободного места на хосте плюс подготовка; эта проверка не доказывает свободное место Docker-store. Вывод control суммарно <=4MiB. Удалять только точные собственные ресурсы после проверки labels/names; доступные журналы предварительно сохранить. Утраченное временное содержимое volume не восстанавливается по журналам.

При ошибке/OOM/таймауте/недостоверных обязательных данных текущая попытка завершается отказом, без повтора и роста лимитов. При неопределённом закрытии живой контроллер удерживает heavy-lock до ручного восстановления. Нормальное завершение и отсутствие собственных ресурсов дают лишь scoped cleanup, не доказательство физического освобождения всего Docker backend.

Сохранить фактические exit/OOM/inspect preparer, исходный ограниченный RAW и ERROR.facts: фиксированные operation/path labels, errno/null и доступные pre-operation actor/file metadata. Метаданные справочные и неатомарные, не свидетельство файлового дескриптора. Секреты, аргументы и текст исключения не логировать. Отдельно указать, что наблюдение новой попытки не доказывает задним числом причину старой.

Перед вопросом владельцу: завершить controller/bootstrap; проверить отказные пути и запрет перехода к service/driver; независимые CODE/TESTER/REVIEWER; точные SHA исходников, старых ELF и всех входов; inert admission с новым purpose/decision и разовым claim. Поля owner_approved/allow_recovery_hold остаются false до нового явного допуска.

PREPARED означает только успех подготовки. Это не SG32 useful work, память corsad/service-group, пригодность512МБ, G2, активация или выпуск. Коммит выполняет владелец отдельно.

## Проверка исходников и привязка байтов

ROOT выполнил независимо проверенный изолированный pure-набор: **34 метода /152 вложенных сценария PASS**, без ошибок, отказов и пропусков. Сохранены исходные stdout/stderr, результат и одинаковые снимки до/после. SHA-256 результата: `f95ddf3b55afb5ba08bcfa09602eb68fbf1f575b09d530af0a03040740ed17eb`. Прежние28/128 проверок сохранены; шесть методов/24 сценария проверяют разделение профилей и отказы по допуску/байтам, загрузку захваченных модулей, запрет runtime-команд, ошибочное копирование и однократный start, четыре исхода обработки и recovery HOLD при ошибке записи результата. Настоящие функции контроллера, границы команд и очистки работают с контролируемой границей родительского CLI/интерактивного дочернего процесса и обычными собственными файлами. Это не настоящий Docker, kernel DAC, OOM или доказательство физической остановки. Приложения и компилятор не запускались.

Неизменяемый пакет исполнения должен связывать следующие байты исходников и прежнюю пару артефактов.
