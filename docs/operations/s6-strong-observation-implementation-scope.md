## 2. Source contract and gaps / Контракт источника и пробелы

Record the actual artifact SHA, source/build attribution when available, node identity, boot identity, process instance identity, source/schema version and a monotonic event sequence. A timestamp or `started_at` alone is not an instance identity. Start from an atomic baseline under the same owner lock as mutations; attach the source before releasing that baseline. End each covered segment with an atomic sequence/state snapshot. A restart, skipped sequence, missing start/end boundary, overflow, unavailable source or invalid duration clock makes the affected interval UNKNOWN. Restart may start a new independently covered segment; it never bridges an unobserved gap. Partial evidence may prove a violation but cannot prove absence of one.

Фиксировать SHA реально работающего артефакта, доступную связь с source/build, identity узла, boot/process instance, версию источника/schema и монотонный sequence. Один timestamp/`started_at` не идентифицирует процесс. Начальный и конечный baseline согласованы с изменениями тем же owner-lock. Рестарт, пропуск sequence, отсутствующая граница, overflow, недоступный источник или невалидные часы делают затронутый интервал UNKNOWN. Новый полный сегмент допустим; пробел между сегментами не склеивается. Частичные данные могут доказать нарушение, но не отсутствие нарушений.

Use fixed per-criterion accumulators where these preserve the exact predicate (K9 durations, K10 code histogram, K12 run state). Poll gaps do not by themselves lose transitions that the verified accumulator retained, but an unclosed final segment cannot be treated as complete. K3 needs enough ordered set changes or a validated equivalent interval proof to reconstruct the global predicate. Any retained transition buffer must be bounded with explicit overflow/gap state; its capacity, transport, cadence and storage costs require concrete review before deployment. No new numerical capacity or polling workload is selected here. Existing asynchronous ebus delivery is insufficient as the sole source: a full inbox drops, and zero subscribers also reports `(0,0)`.

Использовать постоянные агрегаты по критерию, если они сохраняют точный предикат: длительности K9, histogram кодов K10, состояние run K12. Пропущенный опрос не теряет уже сохранённые точные переходы, но незакрытый последний сегмент не считается полным. Для K3 нужна восстанавливаемая история множеств либо доказанный эквивалент. Буфер переходов ограничен, overflow явно превращается в gap; ёмкость, доставка, частота и стоимость хранения отдельно ревьюятся. Новых численных лимитов здесь нет. Один ebus недостаточен: inbox может отбросить событие, а отсутствие подписчиков также даёт `(0,0)`.

## 4. K5: honest load is a required independent fact / Честная нагрузка — отдельный факт

An unauthenticated refused TCP attempt has no trustworthy application identity. Even an authenticated identity does not prove benign intent. Proposed evidence is a separately identified, permitted benign workload with exact attempted actions, actual start/end coverage, expected connection residence and attempted/rejected outcomes joined to the same gate. It must be attributable independently of the observer's refusal decision. This proposal does not authorize that workload or classify arbitrary public traffic as honest.

У отказанной до auth TCP-попытки нет достоверной application identity; даже auth identity сама по себе не доказывает добросовестность. Предлагается отдельно опознаваемая разрешённая добросовестная нагрузка: действия, начало/конец покрытия, ожидаемое время занятости и исходы попыток, связанные с тем же gate независимо от решения об отказе. Нагрузка здесь не разрешается; произвольный публичный трафик не объявляется честным.

**Owner-selected K5 rule:** for each anchor and fixed UTC day, sum the duration of the union of intersections between the full global node-gate state and independently confirmed permitted benign-load intervals. Count overlaps once, sum disjoint covered intervals and split at UTC midnight. Strictly **>3600 seconds/day** establishes **P investigation, not automatic STOP**; refusal-event counts remain separate. Missing coverage is not zero: a confirmed lower bound already >3600 seconds establishes P; otherwise insufficient evidence means UNKNOWN. Arbitrary public traffic is not confirmed benign load, and workload is not authorized. This numerical K5 rule is an explicit exception to the other unapproved thresholds.

**Утверждённое правило K5:** для каждого anchor и фиксированных UTC-суток суммировать длительность объединения пересечений состояния заполненного глобального node-gate и независимо подтверждённых интервалов разрешённой добросовестной нагрузки. Перекрытия считать один раз, непересекающиеся подтверждённые интервалы суммировать, разделять в UTC-полночь. Строго **>3600 секунд/сутки** доказывает **P — разбор, не автоматический STOP**; количество отказов отдельно. Пропуск покрытия не равен нулю: подтверждённая нижняя граница уже >3600 секунд доказывает P; иначе недостаточное свидетельство означает UNKNOWN. Произвольный публичный трафик не объявляется добросовестным; нагрузка не разрешена. Это численное правило K5 — явное исключение из остальных неутверждённых порогов.

## 5. K11: actual endpoint, causal bounds and unchanged baseline / Точка доставки, причинные границы и неизменённая база

**Owner-selected K11 endpoint:** the first successful durable application-message commit at the final recipient, the same endpoint on the candidate and the unchanged previous-release artifact. Relay handling and receipt emission/reception are not delivery; a duplicate cannot reset the first point. Correlate exact message ID, sender, recipient and original attempt, with validated time brackets and clock uncertainty; otherwise UNKNOWN. Authenticated decryption/application availability is a separate fact, not inferred from durable commit. Old-artifact observability remains to be verified. The p95 multiplier, workload, resources and release remain unapproved. The existing background emitDeliveryReceipt/deliveredReceiptFor path stamps receipt creation, including a new timestamp for duplicate resend; storeDeliveryReceipt stamps local ObservedAt. Neither is automatically the selected first durable commit.

**Утверждённая точка K11:** первый успешный durable commit application-message у конечного получателя, одинаковая точка на candidate и неизменённом артефакте previous release. Relay, отправка и приём receipt не являются доставкой; duplicate не сбрасывает первую точку. Нужны точные message ID, sender, recipient и исходная попытка, проверенные временные brackets и неопределённость часов; иначе UNKNOWN. Аутентифицированная расшифровка/доступность приложению — отдельный факт, не выводимый из durable commit. Наблюдаемость старого артефакта ещё требует проверки. Множитель p95, нагрузка, ресурсы и выпуск остаются неутверждёнными. Существующий background emitDeliveryReceipt/deliveredReceiptFor ставит время создания receipt, включая новое время при duplicate resend; storeDeliveryReceipt ставит локальный ObservedAt. Ни одно не равно автоматически выбранному первому durable commit.

For the selected first-durable-commit endpoint, correlate the original scheduled action and exact immutable message ID, sender, recipient and attempt identity. One canary token resolved from chatlog is only usable after the selected unchanged artifact's API, bounded response and unambiguous matching are verified; pending success alone supplies no ID or successful send. Capture a bracket around the actual endpoint if a single exact timestamp cannot be obtained. A post-return timestamp alone is an upper bound, not the commit instant. Include the sender-call bracket, receiver bracket, timestamp read error, offset, drift, suspend and step uncertainty in a common validated time domain. Raw UTC subtraction and NTP “synced” status alone do not supply a numerical bound.

Связать исходное назначенное действие с точным immutable message ID, sender, recipient и attempt. Поиск token в chatlog допустим только после проверки API, ограниченного ответа и однозначности на выбранном неизменённом артефакте; pending не даёт ID/успешную отправку. Если точный timestamp недоступен, ограничить настоящую точку bracket-ом. Timestamp после return — верхняя граница, не момент commit. В общей проверенной шкале учитывать sender/receiver bracket, погрешность чтения, offset, drift, suspend и steps. Простое вычитание UTC и статус NTP «synced» не задают численную границу.

For a same-ID causal endpoint with sender time in `[sL,sU]` and receiver time in `[rL,rU]`, the delay lies in `[max(0,rL-sU), max(0,rU-sL)]` only if the identity, causal order and clock bounds are validated and consistent. Otherwise UNKNOWN. An authenticated causal receipt observed by the sender can give a conservative upper bound even without clock synchronization; it cannot by itself give a useful positive receiver-delivery lower bound. A previous “not delivered” poll is not such a lower bound unless its semantics exclude an earlier delivery whose status has not propagated.

При доказанных ID/причинности и часах задержка ограничена `[max(0,rL-sU), max(0,rU-sL)]`. Несогласованные границы — UNKNOWN. Причинный receipt у sender может дать консервативную верхнюю границу без синхронизации, но сам не даёт полезную положительную нижнюю границу фактической receiver-delivery. Предыдущий отрицательный poll её не задаёт без доказательства семантики распространения статуса.

A sufficient conservative p95 comparison is `candidate p95(upper delays) <= selected multiplier × previous-release p95(lower delays)` on the same selected per-route/day all-attempt population and matched baseline. Keep every matured scheduled attempt: failures, no/ambiguous ID and asynchronous failures are not dropped; unresolved outcomes widen the quantile bounds (potentially to infinity). Do not calculate a successes-only p95 or pool away a bad direction. This keeps the existing proposed multiplier/denominator policy visible; it does not approve those numbers or the proposed 96/route/day, 1152/day, 5-second polling workload. A zero baseline lower bound normally cannot prove a finite positive candidate ratio; report the bound, do not substitute first-observed latency.

Достаточное консервативное сравнение: `p95(candidate upper) <= выбранный множитель × p95(previous lower)` на одинаковой выбранной полной совокупности route/day и сопоставимой базе. Не удалять зрелые попытки с ошибкой, неоднозначным ID или async failure; неизвестные исходы расширяют границы квантиля вплоть до бесконечности. Не считать p95 только успехов и не прятать плохое направление pooling-ом. Числа множителя,96/маршрут/сутки,1152/сутки и polling5с остаются предложениями. Нулевая нижняя база обычно не доказывает отношение для положительной задержки; это не повод заменить метрику first-observed.

**Previous release capability check is the first K11/K16 unit:** name the exact original artifact/hash/platform and retain it unchanged. Inventory its actual RPC/event/store interfaces and prove their endpoint/correlation and loss semantics. An external observer is acceptable only after demonstrating, on that same artifact, the actual endpoint and time brackets, complete coverage, permissions/overhead and restart/drop detection. Packet capture, TLS ciphertext timing, TCP FIN and a current-source symbol name do not prove application delivery or disconnect cause. A read-side database observation may provide an upper bracket; without a genuine lower bracket it may still be insufficient for the p95 comparison. Rebuilding the old release with hooks changes the artifact and cannot close its original baseline. No exact selected previous artifact/capability proof is supplied by this static packet. If it cannot expose or be safely observed at the required point, raise **p95 K11 and/or K16 for that artifact and deployment**, with the missing fact; retain UNKNOWN and request an explicit resolution. This is not a claim that all A criteria are impossible.

**Первый unit K11/K16 — возможности previous release:** выбрать точный исходный artifact/hash/platform и оставить бинарник неизменным. Проверить реальные RPC/event/store интерфейсы, точку, корреляцию и потери. Внешнее наблюдение допустимо только после доказательства на том же артефакте точки/bracket, полноты, permissions/overhead и обнаружения рестартов/drop. Packet capture, TLS timing, TCP FIN и имя функции из current source этого не доказывают. Чтение БД может дать верхнюю границу, но без настоящей нижней её может не хватить для p95. Пересборка old с hooks меняет артефакт. В этом статическом пакете выбранного previous artifact и доказательства API нет. Если нужную точку на нём невозможно безопасно наблюдать, поднять именно **p95 K11 и/или K16 для этого артефакта и deployment**, указав недостающий факт; UNKNOWN сохраняется до явного решения. Остальные A этим не объявляются невозможными.
