# Process load-stand infrastructure

## English

This is an implemented functional slice of the [load-stand decision](design/loadstand-implementation-decision.md). T5 remains incomplete. It does not produce resource acceptance, baseline/candidate measurements, T6 controls, T7 runs, or the final 13b-D1 result.

`internal/testutil/loadstand/sdkedge` is a real SDK child: it creates its own identity with `sdk.EnsureIdentityFile`, initializes `sdk.NewWithContext`, and runs the normal DesktopClient, DMRouter, event bus, and SQLite stack. Its profile explicitly names identity, durable identity-intent, trust, peers, SQLite, and download paths. The functional smoke opts client nodes into listening so two isolated processes can exercise their real DM path directly. That topology is not the measured non-listening edge profile, a headless full-node cost measurement, or a full GUI.

The parent supplies only a sealed environment: PATH, HOME, TMPDIR, TZ, GOMAXPROCS, and seven LOADSTAND settings (data directory, listen/RPC addresses, explicit bootstrap, listener flag, RPC user/password). RPC credentials have 256 bits of entropy, remain in the child environment, and never occur in argv or the public configuration/provenance DTO. Their formatter redacts them and JSON serialization refuses. Ambient `CORSA_*` settings other than `CORSA_VERSION` refuse launch; production bootstrap defaults are replaced rather than appended. The child disables core dumps before identity initialization.

The macOS functional runner requires `sandbox-exec`, numeric `127.0.0.1` addresses, and an explicit nonempty bootstrap plan. Its SBPL profile denies outbound/bind operations except planned local TCP ports. SBPL's `localhost` includes local machine interfaces, so the guarantee is local-host plus explicit-port isolation; configuration constrains all actual endpoints to loopback. It is not a namespace guarantee. The functional controls verify unsandboxed access to our own listener, kernel refusal of an unplanned own-interface service, refusal of a nonlocal documentation-range address on an otherwise permitted port, and successful planned SDK traffic with nonempty connected `fetchPeerHealth`. Arbitrary errors or timeouts do not count as a kernel refusal. Linux refuses this runner until a real namespace implementation exists.

Each process has one `Cmd.Wait` owner. Readiness requires authenticated node identity, complete fresh R1 diagnostics, and a listening socket when requested. SIGTERM drains the SDK lifecycle; restart requires the same public identity. Closing a process RPC handle permanently fences it and cancels active reads, so an old handle cannot reopen against a restarted process at the same address. A forced kill is an error, not a graceful stop.

`ProcessSource` provides typed status, A4 runtime readings, R1 ban observations, transport traffic, session outcomes, route cardinality, mode selection, neighbour composition, enabled-datagram metrics/reverse state, and resource floors. The existing `loadStandNodeSource` has a test-only bridge; an authenticated real-RPC regression samples all its families through the current node producers. Missing old-release families, required nested fields, or `null` counters fail the sample rather than becoming zeros. Schema fields require exact canonical names: alternative spellings equal under JSON's ASCII/Unicode case fold are rejected, including aliases of optional ban expiry. Arbitrary diagnostic counter labels retain their spelling and may differ only by case. Enum names and every current census capability are explicit; owner-declaration guards require adapter review when those sets or R1 families change. Counter families retain their own process start/read timestamps. Datagram totals are checked against the same per-mode reads; independently read counters are not treated as one atomic snapshot. Resource memory gauges reconstruct each subsystem floor and the total; saturation gauges contribute no bytes. These floors do not measure actual heap cost.

R1 reads every current provider/local/remote ban family and loopback score/ban aggregates. Default policy exempts only local self-identity cooldown; strict policy includes it. The injected controller clock must share the node's clock domain: the node's fresh observation barrier must begin after the request starts and finish before it returns. False readiness/freshness, unavailable loopback penalties, stale/future observations, or clock reversal fail the sample. HTTP 404/503 from datagram diagnostics remains unavailable. `getDatagramRuntimeState` now reports versioned constructor/configuration facts: the original requested flag, initialized/configured-off/failure outcome, public identity and Service start. The process sampler requires an immutable binding from the completed start receipt; in-process sampling uses the same authority. Only a bound `configured_off` yields a disabled refusal with no metric value. Constructor failure, old/missing schemas, nil provider and raw `enabled:false` do not prove off. These facts are not serving readiness; existing ownership, listener/fresh-ban barriers and all strict sample/window gates remain separate. ReadAt is diagnostic, with no new max-age or host/VM clock synchronization. No datagram capability/wire or resource/legacy admission changes.

Launch provenance contains the child PID, launch timestamp, platform, and SHA-256 of the launch file. `running_executable_verified` and `kernel_start_time_available` are explicitly false: the launched-file hash does not prove the running executable or prevent PID reuse. The separate [Linux observation foundation](design/loadstand-linux-sampler.md) now verifies actual executable descriptors and PID/start bindings under a same-UID functional helper, with explicit external-metric availability. Its integration into a Linux node launcher, process-group/resource limits, fail-closed namespace orchestration, and complete T5 orchestration remain open.

The smoke sends through normal authenticated `sendDm` and observes normal SDK decrypted notifications inside the identity-owning child. The child exports only message ID, sender/recipient identities, and a body SHA-256 receipt. The parent checks sealed chatlog persistence and SQLite format across graceful restart, then a normal reply from the restarted sender. Identity private material never moves to the parent. Before successful child exit, the child scans its public log and receipts for its signing key, seed, box key and RPC credential in binary, hex, base64 variants, and decimal byte formatting. Public artifacts are bounded to 8 MiB per scan; oversized/unreadable artifacts fail. Parent-owned credential scans also cover public provenance.

Run the functional suite with `go test ./internal/testutil/loadstand/... ./sdk`; the real process smoke is skipped by `-short` and requires macOS. This is ordinary functional verification and does not authorize heavy measurements or change production defaults.

The [final-accounting boundary](design/loadstand-final-accounting.md) provides a normal SDK post-join transport snapshot and an exact ten-key report through a launch-retained private FD. One waiter seals owned-command exit/usage before Done; a separate reducer validates the original root/inode afterward against the completed StartReceipt and two prior counter high waters. Clean supported children may produce FinalExact, including shutdown tail. Failed/forced/unconfirmed/missing/malformed outcomes never become zero. This does not attest the SDK PID behind the sandbox wrapper or admit resources/legacy comparisons.

## Русский

Это реализованный функциональный срез [решения по стенду](design/loadstand-implementation-decision.md). T5 остаётся незавершённой. Срез не даёт приёмки ресурсов, замеров baseline/candidate, контролей T6, прогонов T7 или финального результата 13b-D1.

`internal/testutil/loadstand/sdkedge` — настоящий SDK-процесс: он создаёт собственную identity через `sdk.EnsureIdentityFile`, инициализирует `sdk.NewWithContext` и запускает обычные DesktopClient, DMRouter, шину событий и SQLite. Профиль явно задаёт пути identity, долговременных identity-intent, trust, peers, SQLite и загрузок. Функциональный smoke явно включает listener у двух client-узлов для проверки их нормального прямого DM-пути. Эта топология не является измеряемым профилем edge без listener, замером стоимости headless full-node или полноценным GUI.

Родитель передаёт только закрытый список переменных: PATH, HOME, TMPDIR, TZ, GOMAXPROCS и семь настроек LOADSTAND (каталог данных, адреса listen/RPC, явный bootstrap, флаг listener, RPC user/password). RPC-credentials имеют 256 бит энтропии, остаются в окружении child и не попадают в argv или публичные DTO конфигурации и происхождения процесса. Форматтер скрывает их, JSON-сериализация отказывается. Переменные `CORSA_*`, кроме `CORSA_VERSION`, в окружении родителя запрещают запуск; production bootstrap заменяется, а не дополняется. Child отключает core dump до инициализации identity.

Функциональный macOS runner требует `sandbox-exec`, числовые адреса `127.0.0.1` и явный непустой bootstrap-план. SBPL запрещает outbound/bind, разрешая только запланированные локальные TCP-порты. В SBPL `localhost` включает интерфейсы локальной машины, поэтому гарантия ограничена локальной машиной и явными портами; конфигурация ограничивает реальные endpoints loopback. Это не гарантия namespace. Функциональные контроли подтверждают доступ без sandbox к собственному listener, отказ ядра для незапланированного сервиса на собственном интерфейсе, отказ для нелокального адреса из документационного диапазона на разрешённом порту и успешный SDK-трафик по плану с непустым списком подключённых `fetchPeerHealth`. Произвольная ошибка или таймаут не считаются отказом ядра. На Linux runner отказывается работать до реализации настоящих namespace.

У каждого процесса ровно один владелец `Cmd.Wait`. Readiness требует аутентифицированную identity узла, полную свежую диагностику R1 и открытый listener, если он запрошен. SIGTERM завершает SDK lifecycle; повторный запуск требует прежнюю публичную identity. Закрытие RPC handle окончательно запрещает его использование и отменяет активное чтение: прежний handle не может подключиться к новому процессу на том же адресе. Принудительный kill считается ошибкой, а не корректным завершением.

`ProcessSource` предоставляет типизированные status, A4 runtime, наблюдения банов R1, transport traffic, session outcomes, число маршрутов, mode-selection, neighbours, метрики/reverse-state включённого datagram и resource floors. Для существующего `loadStandNodeSource` реализован мост только в тестовом стенде; функциональный тест через настоящий аутентифицированный RPC читает все его семейства из текущих producers узла. Отсутствующее семейство старого релиза, обязательное вложенное поле или `null`-счётчик приводят к отказу sample вместо подстановки нуля. Поля схемы требуют точных канонических имён: альтернативные написания, эквивалентные по ASCII/Unicode case fold JSON, отвергаются, включая aliases необязательного срока blacklist. Произвольные labels диагностических счётчиков сохраняют написание и могут отличаться только регистром. Имена enum и все текущие capability census заданы явно; проверки деклараций владельца требуют пересмотра адаптера при изменении этих наборов или семейств R1. Счётчики сохраняют собственные timestamps начала процесса и чтения. Итоги datagram сверяются с теми же per-mode readings; независимо читаемые счётчики не считаются атомарным snapshot. Memory gauges восстанавливают floor каждого subsystem и общий итог; saturation gauges не добавляют байтов. Эти floors не измеряют фактическую стоимость heap.

R1 читает все текущие provider/local/remote семейства банов и агрегаты loopback score/ban. Обычная политика исключает только локальный self-identity cooldown; строгая включает его. Внедрённые часы контроллера должны находиться в одном clock domain с узлом: свежий барьер наблюдения начинается после начала запроса и заканчивается до его возврата. Ложные readiness/freshness, недоступные loopback penalties, старое/будущее наблюдение или обратный ход часов приводят к отказу sample. HTTP 404/503 диагностики datagram остаётся unavailable. `getDatagramRuntimeState` теперь сообщает версионированные constructor/configuration facts: исходный requested flag, outcome initialized/configured-off/failure, публичную identity и старт Service. Process sampler требует immutable binding из завершённого start receipt; in-process путь использует тот же authority. Только связанный `configured_off` даёт disabled refusal без значения метрик. Ошибка конструктора, старый/отсутствующий schema, nil provider и сырой `enabled:false` не доказывают off. Это не serving readiness: ownership, listener/fresh-ban barriers и все строгие sample/window gates остаются отдельными. ReadAt диагностический, без нового max-age или синхронизации часов host/VM. Datagram capability/wire и ресурсный/legacy допуск не меняются.

Происхождение запуска содержит PID child, timestamp запуска, платформу и SHA-256 запускаемого файла. `running_executable_verified` и `kernel_start_time_available` явно равны false: хеш файла запуска не доказывает исполняемый файл работающего процесса и не защищает от переиспользования PID. Отдельная [Linux observation foundation](design/loadstand-linux-sampler.md) проверяет настоящий executable FD и PID/start под same-UID функциональным helper, явно отмечая доступность внешних метрик. Integration в Linux node launcher, process-group/resource limits, fail-closed namespace orchestration и полная оркестрация T5 остаются открытыми.

Smoke отправляет через нормальный аутентифицированный `sendDm`, а нормальные SDK-уведомления с дешифровкой наблюдает внутри child, владеющего identity. Child выдаёт только ID сообщения, identity отправителя/получателя и SHA-256 тела. Родитель проверяет сохранение sealed chatlog и формат SQLite после корректного перезапуска, затем нормальный ответ перезапущенного отправителя. Приватные identity-данные не передаются родителю. До успешного выхода child проверяет публичные log и receipts на signing key, seed, box key и RPC credential в бинарном, hex, вариантах base64 и десятичном представлении байтов. Проверка ограничивает каждый артефакт 8 МиБ; слишком большой или нечитаемый файл означает отказ. Проверки credentials в родителе также охватывают публичный provenance.

Функциональный набор запускается командой `go test ./internal/testutil/loadstand/... ./sdk`; настоящий process smoke пропускается с `-short` и требует macOS. Это обычная функциональная проверка: она не разрешает тяжёлые замеры и не меняет production defaults.

[Граница итогового учёта](design/loadstand-final-accounting.md) предоставляет post-join transport snapshot обычного SDK и отчёт ровно из десяти полей через private FD запуска. Единственный waiter фиксирует owned-command exit/usage до Done; отдельная reduction проверяет исходный root/inode, completed StartReceipt и два counter high waters. Чистый поддерживаемый child может дать FinalExact с shutdown tail. Failed/forced/unconfirmed/missing/malformed исходы не становятся нулём. Это не аттестация SDK PID за sandbox wrapper и не допуск ресурсов/legacy.
